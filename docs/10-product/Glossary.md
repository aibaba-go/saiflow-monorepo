# SaiFlow — 术语表

> **领域术语的唯一事实来源。** 其他所有文档均链接至此，不应重复定义术语。AI 代理必须使用这些精确的术语和含义。

## 1. 产品与业务术语

| 术语 | 定义 |
|------|------|
| **SaiFlow** | 本产品：面向泰国 SME 制造企业纸质单据的 OCR 数字化录入系统。标语：“We turn paper into process.”（将纸张变为流程。） |
| **SME** | Small and Medium Enterprise（中小型企业）；目标客户群体。 |
| **上游 / 下游** | 制造企业单据流中的供应商（上游）和客户（下游）。 |
| **卖方场景** | 企业作为卖方：生产与开票（客户 PO → SO → Delivery Note → Invoice）。 |
| **买方场景** | 企业作为买方：收货与付款（Invoice/DN → 3-way match → AP → 付款）。 |
| **Local-first** | 默认在客户本地计算机上存储和处理数据；不强制上传云端。 |
| **Human-in-the-loop** | 在录入或归档前，由人员复核/更正 OCR 输出。 |
| **租户（Tenant）** | 业务数据的归属单位。每份单据及相关业务记录都属于一个租户；用户与租户为多对多关系（PRD §4.9）。 |
| **个人租户（Personal tenant）** | 每个用户自动拥有的租户；不能邀请成员。 |
| **团队租户（Team tenant）** | 用户“升级为团队用户”时另建的租户，对应 Starter 及以上套餐；可邀请成员（受成员人数上限约束）。升级只需付费，不需要企业认证；原个人租户保留。 |
| **企业认证（Enterprise verification）** | 团队租户可随时申请的可选认证：用户提交认证材料、平台管理员审核后开通，或由平台管理员在后台直接开通。不影响升级、付费与业务功能，只改变身份显示；后续开发票功能以其为前提。 |
| **游客（Guest）** | 未注册即试用的访客。进入时建立临时租户并开通一个月 Kinder；注册成功后其数据归入本人的个人租户。 |
| **关联身份（Linked identity）** | 指向内部唯一用户 ID 的外部或联系身份：LINE 身份 ID、邮箱、手机号，以及将来的 Google / Facebook OAuth。 |
| **套餐（Plan）** | 按月扫描配额与成员人数上限划分的四个档位：Kinder / Starter / Intermediate / Advance；可按月或按年开通，续费与升级线下办理。 |
| **OCR 扫描次数（OCR scans）** | 套餐的唯一计量单位：每识别一页计一次；失败或取消的识别不计入。 |
| **月扫描配额（Monthly scan quota）** | 套餐每月可用的 OCR 扫描次数（Kinder 1,000 / Starter 5,000 / Intermediate 10,000 / Advance 100,000）；按泰国时区自然月统计，月底清零、不结转，套餐有效期内次月按档位重新发放。 |
| **免费额度（Free quota）** | Kinder 与 Starter 用户注册后获赠的一次性 OCR 扫描次数，用完为止，每个用户只送一次；默认 100 次，由平台管理员在后台配置；与自动开通的一个月 Kinder 叠加，识别时先扣免费额度。 |
| **成员人数上限（Member limit）** | 每个租户可拥有的成员人数，按套餐档位设定（默认 Kinder 1 / Starter 2 / Intermediate 5 / Advance 不限），由平台管理员在后台配置。 |
| **用量提醒** | 当月剩余扫描配额不足 20% 时一次、月末前 3 天仍有剩余配额时一次的提醒；团队租户发给 owner，个人租户发给本人；同一周期同一节点只一次，不补发。 |
| **到期提醒** | 在套餐到期前 7 天、3 天、1 天、到期当天与到期后各一次的提醒；同一周期同一节点只一次，不补发。渠道见 PRD §4.9“通知渠道”：站内通知、LINE OA 消息、邮件，Intermediate 与 Advance 另加短信。 |
| **LINE OA** | LINE Official Account（官方账号）；底部菜单提供 `register` 注册入口。 |
| **LINE Provider** | LINE 开发者平台中的服务提供方；同一 Provider 下的渠道对同一用户给出相同的 LINE 身份 ID（NFR-COMPAT-008）。 |
| **LINE 小程序** | 运行于 LINE LIFF 的移动端入口：游客试用、上传、核验、确认与管理操作。 |
| **web-pc 企业版** | 面向企业管理层的 PC 端入口：浏览结构化数据与管理操作。 |
| **web-pc admin 后台** | 平台管理员使用的 PC 端运营后台，以独立账号登录。 |
| **到期即停（Hard stop on expiry）** | 套餐到期后不能新建识别，历史单据与结果仍可查看、导出。 |

## 2. 文档类型（规范枚举 `DocumentType`）

| 术语 | 泰语 | 定义 |
|------|------|------|
| **Purchase Order（PO）** | ใบสั่งซื้อ | 客户/买方发出的订单单据，指定项目、数量和价格。 |
| **Delivery Note（DN）** | ใบส่งของ | 随已交付货物附送的单据；列明已交付项目和数量。 |
| **Delivery Order / Instruction** | ใบสั่งจ่าย | 分发、包装和特殊处理的指示（固定字段与自由文本混合）。 |
| **Invoice** | ใบแจ้งหนี้ / ใบกำกับภาษี | 要求付款的账单单据；可能是税务发票。 |
| **Receipt** | ใบเสร็จ | 已收到付款的凭证。 |
| **Credit Note** | ใบลดหนี้ | 从发票总额中扣减金额的单据（退货/折扣）。 |
| **Tax Receipt / Withholding Tax** | หนังสือหักภาษี ณ ที่จ่าย | 付款后保留的税务单据；可为税务目的检索。 |
| **Bill** | บิล | 包含周期、金额、税额和结算方式的对账单。 |

## 3. 数据与处理术语

| 术语 | 定义 |
|------|------|
| **OCR** | Optical Character Recognition（光学字符识别）：将图像/PDF 转换为机器可读文本。 |
| **AI-OCR extraction** | 使用能理解版式和表格的模型，在 OCR 基础上提取结构化字段。 |
| **字段（Field）** | 从文档提取的单个具名数据元素（例如 `po_number`、`total_amount`）。 |
| **置信度评分（Confidence score）** | 表示模型对提取字段确定程度的 0.0–1.0 值。 |
| **行项目（Line item）** | 文档项目表中的一行（产品、数量、单价、金额）。 |
| **数据主档 / 主数据（Data master / Master data）** | ERP 中的参考数据：客户主档、供应商主档、物料主档、价目表、收货地址。 |
| **主数据映射（Data master mapping）** | 将提取字段与主数据匹配；未匹配项 → 标记以供核验。 |
| **3-way matching** | 在容差范围内对账 Invoice ↔ PO ↔ Delivery Note（数量、价格、总额）。 |
| **容差（Tolerance）** | 匹配允许的偏差（数量容差、价格容差、总额比较）。 |
| **标记以供核验（Flag for review）** | 标记需人工核验的文档/字段（低置信度、未匹配、不匹配）。 |
| **标准化（Normalization / Standardization）** | 将提取值转换为一致的结构化格式（日期、数值、THB）。 |
| **重复检测（Duplicate detection）** | 识别已处理的文档（例如相同发票编号）以避免重复录入。 |
| **去重（Deduplication）** | 移除/合并重复的文档记录。 |
| **预处理（Preprocessing）** | OCR 前的图像清理：矫正、去阴影、降噪、裁剪。 |
| **双重存储（Dual storage）** | 同时归档原始图像文件与识别/结构化数据文件。 |
| **Merge PDF** | 将多个文档（PO + DN + Invoice）合并为一个账单包 PDF。 |
| **TextIn** | 外部 OCR 与结构化文档识别服务；SaiFlow 仅在服务端调用，并保存其原始 JSON 响应。 |
| **原始识别载荷（Raw extraction payload）** | OCR 引擎（TextIn 或 Google Cloud Vision API）返回、原样保存于 Firestore 的完整 JSON 及其关联元数据；按载荷版本不可变。 |
| **文档格式模板（Document template）** | 已版本化的表单定义：表单类型、字段、明细行、主要字段与界面定义；是大模型模板匹配与结构化转换的依据，也决定 Excel 导入模板与导出版式。 |
| **JSONPath 映射** | v3 不再使用（已由大模型结构化转换取代，PRD OQ-19）；保留词条以便追溯：曾指从原始 JSON 中选择数据并写入既定规范字段的受限路径规则。 |
| **幂等转换（Idempotent conversion）** | 对同一文档与原始载荷版本重复执行时，结果不产生重复记录的转换。 |
| **数据录入入口** | 进入统一业务流程的三种方式：OCR 扫描、结构化文件导入、界面直接录入（PRD §3.1）。 |
| **OCR 扫描** | 拍照、扫描或导入图像/PDF 后经 OCR 与大模型得到结构化数据的录入入口（P0）。 |
| **结构化文件导入** | 按固定导入模板填写的 xlsx / xls 文件上传后按字段名直接解析的录入入口，不调用大模型（P1）。 |
| **界面直接录入** | 选择文档格式模板后在模板界面中直接录入数据的入口（P2）。 |
| **Google Cloud Vision API** | 可配置的 OCR 引擎之一，与 TextIn 并列；仅在服务端调用。 |
| **首选引擎 / 备用引擎** | 平台管理员配置的两个 OCR 引擎及其优先级；首选引擎失败按两层规则切换到备用引擎（PRD §4.6、OQ-12）。 |
| **大模型模板匹配** | 由大模型根据原始识别载荷判断单据对应哪个文档格式模板；无法匹配时弹出模板选择框。 |
| **大模型结构化转换** | 由大模型按选定模板把原始识别载荷转换为模板定义的结构化 JSON，并给出字段置信度。 |
| **字段置信度** | 大模型对每个字段结果确定程度的 0.0–1.0 值（字段级，P1）。 |
| **置信度阈值** | 系统参数：低于该值的字段被标记为低置信度；也是 Confirm all 的判定标准（P1）。 |
| **Confirm all（批量确认）** | 待确认队列中一次性确认所有字段置信度均不低于置信度阈值的表单（P1）。 |
| **人工确认** | 用户在按模板展现的界面中核对、修改并确认识别结果的环节。 |
| **正式业务数据** | 完成确认与（按配置的）复核后的表单数据；报表与导出的依据。与待核验、待复核为同一文档的不同状态（OQ-21）。 |
| **主要字段** | 文档格式模板中定义的必备字段；缺失时 OCR 识别失败，或 Excel 整个文件导入失败。 |
| **隐藏模板标识** | 嵌入导入模板 Excel 中、用于确定单据类型与模板版本的隐藏标记。 |
| **自由格式** | 不使用固定模板，按原始内容自动生成 N 组表头 KV + N 张明细表的结构化数据（P1）。 |


## 4. 角色（见 `Personas.md`）

### 4.1 系统角色与权限

系统只预设**平台管理员**与 **owner** 两个角色；其余角色由 owner 在运行期以权限点组合自定义（PRD §4.9）。

| 术语 | 定义 |
|------|------|
| **平台管理员（Platform admin，简称平台 admin）** | 由维护系统的技术团队担任的跨租户角色：开通/关闭租户、修改租户信息、线下收款后开通团队租户并修改档位与有效期、审核企业认证、配置成员人数上限、配置 OCR 引擎与大模型。使用独立的 admin 后台账号登录；其能力不能分配给租户内角色。 |
| **owner（租户所有者）** | 一个租户的所有者（个人租户的 owner 即本人），拥有本租户全部权限，可定义角色、分配角色、修改默认角色。 |
| **默认角色（Default role）** | 成员加入团队租户后自动获得的角色；owner 可修改其权限。 |
| **权限点（Permission）** | 设计期确定、可组合进自定义角色的最小授权单位，清单见 PRD §4.9。 |

### 4.2 业务角色（用户画像）

以下为业务中的岗位，用于描述用户画像，**不是系统预设角色**；企业可由 owner 按这些岗位自定义角色。

| 术语 | 定义 |
|------|------|
| **文员（Clerk）** | 上传文档并核验 OCR 输出的办公室人员。 |
| **财务人员（Financial staff）** | 处理发票、AR/AP、对账和税务单据。 |
| **仓库管理员（Warehouse administrator）** | 处理 Delivery Note 和库存同步。 |
| **采购专员（Procurement specialist）** | 处理供应商 PO 和收货。 |
| **企业所有者（Enterprise owner）** | 业务岗位：企业主，负责监督和审批；在系统中通常担任其团队租户的 owner（§4.1）。 |
| **业务协调员（Business coordinator）** | 上游/下游合作伙伴处的间接用户。 |

## 5. 标准与缩写

| 术语 | 定义 |
|------|------|
| **PDPA** | 泰国《个人数据保护法》— 管辖个人数据的处理。 |
| **ERP** | Enterprise Resource Planning（企业资源计划）系统（本地和泰国 SME 的不同版本）。 |
| **AR / AP** | Accounts Receivable / Accounts Payable（应收账款 / 应付账款）。 |
| **SO** | Sales Order（销售订单）；PO 校验后在 ERP 中创建的草稿。 |
| **SKU** | Stock Keeping Unit（库存量单位）；区分不同物料/产品的编码。 |
| **THB** | 泰铢（货币）。金额使用 `decimal(14,2)`。 |
| **DPI** | Dots per inch（每英寸点数）；扫描分辨率。目标为等效 ≥ 300 DPI。 |
| **P0 / P1 / P2** | 优先级层级：发布必需 / 迭代 / 长期。 |
| **FR / NFR / AC / TC** | Functional requirement / Non-functional requirement / Acceptance criterion / Test case（功能需求 / 非功能需求 / 验收标准 / 测试用例）。 |
