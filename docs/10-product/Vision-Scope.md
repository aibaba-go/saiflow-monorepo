# SaiFlow — 愿景、范围与发布计划

> 定义产品愿景、明确的范围内/范围外边界以及分阶段发布计划。使用本文档决定某项功能请求属于 V1.0、V2.0 还是 V3.0。

## 1. 愿景

**“We turn paper into process — 从订单到付款，自动化您的单据工作流。”**

SaiFlow 让泰国 SME 制造企业的纸质单据实现数字化、核验并录入企业现有系统，也不要求配备 IT 人员。系统可根据企业当前业务支持不同的单据录入流程，并支持可配置化的单据处理流程。

## 2. 产品原则

1. **私有与安全优先** — 以私有 GCS、Cloud SQL、最小权限 IAM 和审计日志保护数据，并符合 PDPA 约束。
2. **可配置流程优先** — 单据类型、处理步骤、字段映射和业务规则应支持按企业业务进行配置；具体配置模型须在需求层明确后实现。
3. **Human-in-the-loop** — OCR 提出结果，人员在录入前核验；更正会被记录。
4. **零 IT 人员可用性** — 未受培训的文员也能完成流程。
5. **原生混合语言** — 一份单据内混合泰语/英语/中文是常态，而非边缘情况。
6. **适应低质量输入** — 手机照片和家用扫描件是第一等输入。

## 3. 范围

### 3.1 范围内（V1.0 — P0）

- 通过拍照 / 扫描 / 本地导入上传（JPG、PNG、PDF），支持单个与批量。
- 基础预处理（矫正、去阴影、降噪、裁剪）。
- 识别四种核心单据类型 + Invoice 的 OCR；泰语/英语/中文混合。
- 带变更日志的人工核验与更正 UI。
- OCR 结果导出 Excel（与导入模板版式一致）+ 私有 GCS 归档（双重存储）。
- 基础系统：操作日志、语言切换、系统参数配置（OCR 首选/备用引擎、大模型）。
- 三个使用入口：LINE 小程序、web-pc 企业版（数据浏览与管理操作）、web-pc admin 后台（PRD §4.9）。
- 账户与租户：游客试用、LINE 注册与登录、个人与团队租户、运行期自定义角色。
- 计费：四档套餐（按月或按年开通、成员人数上限）、按 OCR 扫描次数计量、一次性免费额度、到期即停、线下续费、用量提醒与到期提醒。

### 3.2 已知业务流程

SaiFlow 应根据企业当前业务支持不同单据处理流程，并支持可配置化的单据处理流程。以下流程已确认属于产品业务范围；其具体字段、状态、参与角色、规则、优先级和验收标准必须先进入 `docs/20-requirements/` 拆解为原子化需求后，方可实现。

| 流程 | 业务目标 | 当前已知单据或数据 | 需求状态 |
|------|----------|--------------------|----------|
| **订单跟踪流程** | 跟踪从订单到付款的单据流转与处理状态。 | PO、Delivery Note、Invoice、Receipt、Credit Note、Tax Receipt | 已有 OCR/录入需求基础；需补充流程状态与关联规则 |
| **应收款与应付款跟踪流程** | 根据订单接收、交付、发票等单据数据跟踪应收款和应付款。 | 订单、Delivery Note、Invoice、Receipt 及关联金额/日期数据 | 待拆解需求 |
| **生产线设备维修状况跟踪流程** | 记录设备巡检结果、维修记录、维修配件采购与申请，并统计维修费用。 | 设备巡检记录、维修记录、配件采购/申请、维修费用数据 | 待拆解需求 |

### 3.3 范围外（延后）

| 项目 | 延后至 |
|------|--------|
| 直接 ERP / 管理系统 API 集成 | V2.0（P1） |
| 在线支付（续费与升级在 V1.0 线下办理） | 未排期 |
| 按租户配置 OCR 引擎与大模型（V1.0 全系统共用一套） | 未排期 |
| web-pc 报表（`EPIC-07`，P1）、应收应付跟踪与异常识别（V2.0） | 见 §4 |
| 单据比对与异常提醒 | V2.0 |
| 3-way matching 自动过账 | V2.0 |
| 预置流程模板与跨企业流程复用 | V3.0 |
| 智能单据分类、历史检索与可追溯性 | V3.0 |
| 持续学习 / 模板管理平台 | V3.0（P2.2） |
| 监控仪表板、企业 SSO、高级合规性 | V3.0（P2.3） |

### 3.4 明确的非目标

- 不是完整的 ERP 或会计系统。
- 不是面向已定义集合以外任意文档类型的通用 OCR API。
- 在应收应付与设备维修流程完成需求拆解前，不将其未定义细节视为既定功能。

## 4. 发布计划与成功指标

| 发布版本 | 主题 | 关键交付物 | 成功指标（KPI） |
|----------|------|------------|-----------------|
| **V1.0** | 纸张 → 可核验的数字流程 | OCR + 核验 + Excel/私有 GCS 归档 + 订单跟踪流程基础 + 账户、租户与计费（LINE 小程序、web-pc 企业版与 admin 后台） | 样本字段准确率 ≥ 85%；单份文档 ≤ 5 s（p95）；文员 < 2 分钟完成一份单据 |
| **V2.0** | 对接 ERP 与应收应付跟踪 | ERP/管理系统同步、比对、3-way match、应收应付跟踪 | 自动录入成功率 ≥ 90%；对账时间 −50% |
| **V3.0** | 扩展、设备维护与治理 | 设备维修流程、分类、检索、可追溯性、流程模板复用 | 搜索检索 < 2 s；端到端无人工介入率 ≥ 60% |

## 5. 假设与约束

- 用户提供等效 ≥ 300 DPI 的文档或清晰的手机照片。
- 企业用户须可访问部署在 Google Cloud Run 的服务；运行环境与浏览器兼容性见 `NFR-COMPAT`。
- 原件存储在私有 GCS Bucket，表单数据（原始识别载荷与结构化结果）存储在 Firestore，系统数据存储在 Cloud SQL PostgreSQL（`docs/30-design/adr/ADR-007-v3-storage-boundary.md`）；PDPA 适用于文档中的所有个人数据（见 `NFR-SEC`、OQ-4）。
