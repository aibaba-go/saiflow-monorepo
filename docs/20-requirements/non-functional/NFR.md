# SaiFlow — 非功能需求（NFR）

> 横切质量目标。每项功能需求均继承这些约束。所有值均可度量，因此可以测试。分类使用 `ID-Conventions.md` 第 3 节定义的代码。

## 1. 性能与可扩展性（`NFR-PERF`）

| ID | 需求 | 目标 | 优先级 |
|----|------|------|--------|
| NFR-PERF-001 | 单份文档端到端识别与转换时间 | 从预处理完成至 OCR 引擎返回与原始载荷保存完成 ≤ **5 s**（p95；不含人工核验）；大模型模板匹配与结构化转换的性能目标见 PRD OQ-20 | P0 |
| NFR-PERF-002 | 每张图像预处理（矫正/裁剪）时间 | ≤ **1 s**（p95） | P0 |
| NFR-PERF-008 | Firestore 载荷到 Cloud SQL 转换延迟 | v3 已废弃：不再有关系投影（PRD OQ-19、ADR-007，现由 ADR-008 取代）；保留 ID 以便追溯 | — |
| NFR-PERF-003 | 批量吞吐量 | 批量模式下 ≥ **200 份文档/小时** | P1 |
| NFR-PERF-004 | 字段级 OCR 准确率（V1.0 基线） | 样本集上 ≥ **85%**；各字段目标 = PRD OQ-1 | P0 |
| NFR-PERF-005 | UI 对用户操作的响应 | 本地操作 ≤ **200 ms** | P0 |
| NFR-PERF-006 | 搜索/检索响应（V2.0+） | 筛选查询 ≤ **2 s** | P1 |
| NFR-PERF-007 | 本地存储读/写 | 导出 ≤ 1000 行 Excel 时无可感知延迟 | P0 |
| NFR-PERF-009 | 调用次数与耗时可观测 | 记录每份单据的 OCR 与大模型调用次数与耗时，供 OQ-20 设定成本上限与性能基线 | P0 |

## 2. 安全与隐私（`NFR-SEC`）

| ID | 需求 | 详细信息 | 优先级 |
|----|------|----------|--------|
| NFR-SEC-001 | 静态加密 | GCS 中的文档与数据库备份启用静态加密；VPS 上数据库与本地备份文件的静态加密方式按 PRD OQ-30 在投产前确定并启用（ADR-008） | P0 |
| NFR-SEC-002 | 私有云对象存储 | 文档字节仅存储于私有 GCS Bucket；不得使用公共 Bucket、匿名访问或由浏览器持有服务凭据 | P0 |
| NFR-SEC-003 | 隔离的操作权限 | 在服务端强制实施 RBAC；访问 GCS 与 Vision 的 GCP 服务账号只授予所需权限（业务桶读写、备份桶写入、Vision 调用）；数据库应用账号只授予所需权限；服务器部署账号只拥有部署所需权限 | P0 |
| NFR-SEC-009 | TextIn 密钥与跨境控制 | TextIn 等外部服务凭据仅存储于服务器上仅管理员可读的环境变量文件（部署所需的值存于 GitHub Secrets），不进仓库与镜像；生产调用须在 OQ-7 的 PDPA 与跨境评估通过后启用 | P0 |
| NFR-SEC-010 | 原始识别载荷保护 | 原始 JSON（PostgreSQL jsonb）按载荷版本不可变；浏览器不得直接读写，访问必须经服务端授权 | P0 |
| NFR-SEC-011 | admin 后台认证 | 平台 admin 后台使用与客户账号隔离的独立账号；口令以强单向哈希存储，连续失败达到阈值后锁定；admin 的每次写操作写入操作日志。短信 OTP 在接入短信平台后补充 | P0 |
| NFR-SEC-012 | 大模型与 OCR 服务的数据处理 | 发送到大模型与 OCR 服务的单据内容仅由服务端调用；更换模型或引擎时由人工确认其 PDPA 合规（PRD §3.6） | P0 |
| NFR-SEC-004 | 记录防篡改 | 变更日志与操作日志仅可追加且经过完整性检查 | P0 |
| NFR-SEC-005 | 可追溯操作日志 | 每项改变状态的操作均记录用户、时间、目标和结果 | P0 |
| NFR-SEC-006 | 密码存储 | 使用强单向哈希（bcrypt/argon2）；不得存储明文 | P0 |
| NFR-SEC-007 | PDPA 合规 | 按泰国 PDPA 处理个人数据；保留/删除策略 = PRD OQ-4 | P0 |
| NFR-SEC-008 | 会话安全 | 空闲会话超时；安全的本地会话 token | P1 |

## 3. 兼容性（`NFR-COMPAT`）

| ID | 需求 | 详细信息 | 优先级 |
|----|------|----------|--------|
| NFR-COMPAT-001 | 操作系统支持 | Windows 10/11 和 macOS（当前版本 −2） | P0 |
| NFR-COMPAT-002 | 输入设备 | 普通手机相机和家用扫描仪 | P0 |
| NFR-COMPAT-003 | 文件格式 | JPG、PNG、PDF（见 FR-UPLOAD-003） | P0 |
| NFR-COMPAT-004 | 办公软件 | 导出文件可在 MS Excel 和 LibreOffice Calc 中正确打开 | P0 |
| NFR-COMPAT-005 | 显示分辨率 | 从 1366×768 到 4K 均可用；响应式布局 | P1 |
| NFR-COMPAT-006 | 非标准纸张格式 | 容忍不同的泰国文档版式/尺寸（A4、A5、连续打印纸） | P0 |
| NFR-COMPAT-007 | ERP 兼容性（V2.0） | 为主流泰国本地 SME ERP 版本提供适配器 | P1 |
| NFR-COMPAT-008 | 同一 LINE Provider | LINE OA、LIFF 小程序与 web-pc 的 LINE 登录必须属于同一个 LINE Provider，使同一用户在各入口得到相同的 LINE 身份 ID | P0 |

## 4. 易用性与无障碍性（`NFR-USAB`）

| ID | 需求 | 详细信息 | 优先级 |
|----|------|----------|--------|
| NFR-USAB-001 | 低操作门槛 | 新文员在接受 ≤ 5 分钟指引后完成上传→核验→导出 | P0 |
| NFR-USAB-002 | 零基础快速上手 | 首次运行向导；合理默认值；无需 IT 设置 | P0 |
| NFR-USAB-003 | 本地化交互 | 完整 UI 提供英语（默认）、泰语、中文（负责人 2026-11-05 改为英语默认） | P0 |
| NFR-USAB-004 | 清晰的错误与状态反馈 | 每项操作均有可见状态；错误经过本地化且可操作。LINE Mini App 的启动、页面、局部请求及按钮等待统一使用 SaiFlow F＋圆点标志、saiflow 字标、扫描光线与环绕光点；保留上传百分比、OCR 阶段及本地化操作文字，完成或失败后停止等待；套餐审核状态不作为网络加载。尊重 `prefers-reduced-motion`，等待状态提供可访问文字，不反复播报上传百分比；窄屏与泰语文案不遮挡输入或操作（AC-NFR-USAB-004-01/02/03） | P0 |
| NFR-USAB-005 | 简单直观的流程 | 从上传到结果的核心流程 ≤ 3 步 | P0 |

## 5. 可靠性与可用性（`NFR-REL`）

| ID | 需求 | 详细信息 | 优先级 |
|----|------|----------|--------|
| NFR-REL-001 | 云服务依赖反馈 | 当 GCS、OCR 引擎（TextIn、Google Cloud Vision）、大模型或数据库不可用时，系统必须显示可操作的失败状态，不得声称离线完成 | P0 |
| NFR-REL-002 | 优雅失败 | 一份失败文档不得中止批次；应标记为失败且可重试 | P0 |
| NFR-REL-003 | 数据持久性 | 处理期间崩溃不得损坏 GCS 原件、原始载荷或已归档文档 | P0 |
| NFR-REL-004 | 恢复 | 重启或事件重放后恢复待处理任务，并通过幂等键避免重复的结构化结果 | P1 |
| NFR-REL-005 | OCR 引擎切换 | OCR 引擎按 PRD §4.6 与 OQ-12 决议执行两层切换：单据级重试后改用备用引擎；首选引擎全局连续失败达到阈值时整体切换并按间隔试探恢复；只统计服务层面的失败 | P0 |

## 6. 数据完整性、存储与保留（`NFR-DATA`）

| ID | 需求 | 详细信息 | 优先级 |
|----|------|----------|--------|
| NFR-DATA-001 | 双重存储 | 每份已归档文档均保留原始图像 + 结构化数据 | P0 |
| NFR-DATA-002 | 可配置阈值 | 可按文档类型/字段配置置信度/核验阈值 | P1 |
| NFR-DATA-003 | 保留策略 | 可按 PDPA（PRD OQ-4）配置保留/删除 | P1 |
| NFR-DATA-004 | 金额精度 | 金额使用 `decimal(14,2)`；不得出现浮点舍入漂移 | P0 |
| NFR-DATA-005 | 备份与导出 | 数据库每天导出一次，VPS 本地保留 7 天，导出完成后立即复制到 GCS 单独的备份桶（保留 30 天）；GCS 对象按其保留策略管理（ADR-008） | P0 |
| NFR-DATA-006 | 原始载荷可追溯性 | 每份结构化结果必须关联原始载荷版本和已发布模板版本；转换不得覆盖原始 JSON | P0 |
| NFR-DATA-007 | 转换幂等性 | 同一 `document_id` 与 `payload_version` 的重试不得重复创建字段或行项目 | P0 |

## 7. 本地化与多语言（`NFR-I18N`）

| ID | 需求 | 详细信息 | 优先级 |
|----|------|----------|--------|
| NFR-I18N-001 | 混合文字系统 OCR | 在同一文档中识别泰语 + 英语 + 简体/繁体中文 | P0 |
| NFR-I18N-002 | 泰语日期/数字格式 | 解析佛历日期和泰语千位分隔符；标准化为规范格式 | P0 |
| NFR-I18N-003 | UI 外部化 | 所有字符串位于资源包中；不得硬编码文本 | P0 |
| NFR-I18N-004 | 货币 | 默认 THB；符号和格式经过本地化 | P0 |

## 8. 参考硬件（用于性能测量）

> 性能目标（NFR-PERF）在此基准上测量；低于该配置的部署可按比例调整目标。

| 组件 | 基准 |
|------|------|
| CPU | 四核 2.0 GHz（2020 年级别） |
| RAM | 8 GB |
| 存储 | SSD，持续写入 ≥ 100 MB/s |
| OS | Windows 10/11 或 macOS 12+ |
