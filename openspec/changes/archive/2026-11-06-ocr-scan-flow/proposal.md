## Why

账户、组织、套餐、通知与三个前端都已上线，但 SaiFlow 的核心业务"把纸质单据变成结构化数据"在重建分支上还不存在。小程序首页的扫描入口和"历史"标签仍显示"即将推出"。这条流程在 main 分支上前后端都已跑通，并在内部演示通过：
- 上传；
- OCR；
- 大模型匹配模板并转换；
- 修改与确认；
- 导出 Excel。

ADR-009 决定只沿用 main 的代码逻辑与库设计，在本分支上重写。

负责人 2026-11-06 做了以下决定：
- 同事暂不参与，全部功能由负责人完成；
- 本 change 按 main 现有逻辑，迁入整条扫描流程：后端服务与接口，加上 LINE 小程序的页面；
- 模板只建表并预置模板，模板配置页以后做；
- OCR 引擎做 TextIn 与 Google Cloud Vision，带首选/备用切换；
- 图像预处理用引擎自带的功能；
- 匹配不上模板时保留 main 的"通用结果"。

## What Changes

**后端（`services/api`，按 ADR-009：A 类模块连同测试迁入，B 类按 main 的规则重写；业务表沿用 main 的结构，只做 T1–T9 的调整）：**

- **上传与原件（FR-UPLOAD-003/004/005/010/011/013，006/009）：**
  - 每个文件分三步上传：建立上传、传内容、完成校验；
  - 接受 JPG、PNG、PDF，按文件内容校验格式，限制大小与页数；
  - 原件存私有 GCS，只能经后端读取；PDF 由后端渲染出各页预览；
  - 上传完成但还没开始识别的文件列为"待处理"，可以删除；
  - 矫正与裁剪交给 OCR 引擎完成。
- **识别任务（FR-OCR-017、022）：**
  - 从待处理文件建立识别任务；同一个防重复标识只建一次；
  - 建立时按页数预占扫描次数，失败或取消时退还（billing FR-SYS-013；套餐到期即停按 FR-SYS-012）；
  - 任务由独立的后台进程处理，可以取消、重新识别、删除结果；
  - 进程重启后恢复未完成的任务；
  - 识别结果没有把握时，按失败处理，不自动重试。
- **OCR 引擎与切换（FR-OCR-021，新）：**
  - 按 ocr-settings 的配置调用 TextIn 或 Google Cloud Vision；
  - 单份单据在首选引擎上重试达到次数后改用备用引擎；
  - 首选引擎全局连续失败达到阈值时，整体切换到备用引擎，并按间隔试探首选引擎；
  - 只统计服务层面的失败（PRD §4.6）。
- **原始结果（FR-OCR-018）：** OCR 原始 JSON 原样存入 PostgreSQL（jsonb），记录所用引擎，写入后不能修改或删除（T7）。
- **模板与匹配（FR-TEMPLATE-006、FR-OCR-019、020、023）：**
  - 建立模板与模板版本表，预置 main 的两个系统模板：Tax Invoice、Billing Note；
  - 大模型在已发布模板中自动匹配，并按所选模板转换为结构化 JSON；
  - 匹配不上时，用户可以选择模板，或选择"通用结果"（负责人 2026-11-06）；
  - 转换失败可以重试，每次重试都是一次新的尝试；
  - 记录每份结果所用的模板版本。
- **结果的修改与确认（FR-VERIFY-015、009、016、006、017）：**
  - 每次保存生成一个新版本，旧版本保留；
  - 并发修改用版本号检测冲突；
  - 确认前检查模板的必填字段，并要求已注册且套餐有效；
  - 确认后结果不能再修改；
  - 任务按阶段列出（识别中、识别失败、模板匹配中、待核验、已确认），可以筛选和分页。
- **导出（FR-ENTRY-015）：**
  - 已确认的结果可以导出为 XLSX：上方是分组的键值信息，下方是明细表，带隐藏的模板标识（PRD §4.4）；
  - 单元格按文字写入，保留前导零；
  - 下载经后端转发，24 小时有效；
  - 给 LINE 内置浏览器提供 60 秒有效的下载凭证。
- **权限与租户：**
  - 所有接口按当前租户执行（X-Tenant-Id）：
    - 建任务需要"上传与识别"；
    - 修改与确认本人的结果需要"核验与确认"，处理他人的结果需要"核验他人单据"；
    - 导出需要"导出"；
    - 没有"数据浏览"的成员只看到本人提交的单据（FR-SYS-002、FR-SYS-017）。
  - 游客可以上传、识别和修改，确认前须先注册。

**LINE 小程序（`apps/line-mini`，按 main 的 Vue 页面逻辑用 React + antd-mobile 重写）：**

- **首页（修改 FR-SYS-056）：** 首页的扫描入口可用，"历史"标签显示历史记录。
- **扫描与上传（FR-SYS-057）：**
  - 拍照或选文件，一次可以选多个；
  - 逐个上传，单个文件失败不影响其他文件；
  - 上传成功的文件进入"待处理"。
- **待处理与开始识别（FR-SYS-058）：**
  - 先预览原件，用户点"开始"才建立识别任务；
  - 扫描次数不足或套餐到期时，给出对应提示。
- **识别进度（FR-SYS-059）：** 按"上传、识别、模板匹配"三步显示进度，可以取消。
- **识别结果（FR-SYS-105）：**
  - 原图在上方，可以放大；
  - 按模板或通用结果显示表头字段与明细表；
  - 可以修改字段、增删表格行、存草稿、换模板，缺少的必填字段醒目标记。
- **确认（FR-SYS-106）：**
  - 确认前检查必填字段；
  - 游客先注册；套餐到期时先保存草稿，再去套餐页。
- **最终结果与导出（FR-SYS-107）：**
  - 查看已确认的结果，导出 XLSX 并下载；
  - 在 Android 的 LINE 内置浏览器里，用下载凭证在系统浏览器中打开。
- **历史（FR-SYS-108）：** 按阶段筛选，向下滚动加载更多，点开进入对应页面。

**部署与文档：**

- **新增的服务器配置：**
  - 私有 GCS 原件桶，以及只能读写该桶的服务账号（凭据放在 `.env`，ADR-008）；
  - TextIn 与 Google Vision 的密钥（B-5b 已定变量名）；
  - 大模型的 AppKey；
  - compose 里新增一个识别进程。
- **文档同步：**
  - PRD §3.2、§4.2：把"通用结果"提前到 V1.0；
  - EPIC-01、EPIC-02、EPIC-03、EPIC-04 中迁入的需求标为已迁移；
  - `Architecture.md`、`Data-Model.md`、`Requirements-Index.md`；
  - ADR-006 §7：B-3 一行写明本 change 的范围，B-4 的范围相应缩小；
  - 部署说明。

## Capabilities

### New Capabilities

- `documents`：上传、原件存储与预览、待处理记录（FR-UPLOAD-*）。
- `recognition`：识别任务与后台处理、OCR 引擎与切换、原始结果、模板与匹配、结构化转换、通用结果（FR-OCR-*、FR-TEMPLATE-006）。
- `results`：结果版本、修改与冲突、确认门控、确认后锁定、按阶段列出（FR-VERIFY-*）。
- `exports`：已确认结果的 XLSX 导出与下载（FR-ENTRY-015）。

### Modified Capabilities

- `line-mini`：
  - 修改 FR-SYS-056：首页扫描入口与"历史"标签可用；
  - 新增 FR-SYS-057、058、059：扫描与上传、待处理与开始识别、识别进度；
  - 新增 FR-SYS-105、106、107、108：结果、确认、最终结果与导出、历史。

## Non-goals

- **一级、二级复核：** 0/1/2 级复核配置、待复核记录、复核日志（FR-VERIFY-010..013），以及写入正式业务数据（B-4）。本 change 的"已确认"就是流程的终点。
- "Confirm all" 批量确认、字段置信度与低置信度标记（PRD 定为 P1）。
- 模板配置页面（EPIC-08，P1）、自由格式模板（P1）、Excel 导入（P1）、界面直接录入（P2）。
- web-pc 与 admin 后台的上传、结果、数据浏览页面（以后单独做）。
- CSV 与 JSON 导出（FR-ENTRY-013，P1）、ERP 对接（P1）、合并 PDF（P1）。
- 系统自己做图像预处理（去阴影、降噪为 P1；矫正、裁剪由引擎完成）。
- URL 导入（main 的 `POST /file-imports`）：PRD 没有要求，并且有访问内网的风险（ADR-009 §6）。
- 迁移 main 的数据（ADR-009：不迁数据）。

## 待负责人确认的假设

| # | 假设 | 理由 |
|---|------|------|
| A1 | 每个文件最大 20 MB；PDF 每个任务最多 50 页；一次最多选 10 个文件 | main 的上限 |
| A2 | 一个文件对应一个识别任务；扫描次数按页数预占（图片为 1 页） | main 的做法；PRD"每识别一页计一次" |
| A3 | 游客可以上传、识别、修改并保存草稿，确认前须注册；注册后游客的任务与结果归入个人租户（B-2a 的数据归集） | PRD §4.9：游客可使用上传、识别与核验，确认时注册 |
| A4 | 确认后的结果在本 change 中不能再修改；以后由 B-4 的复核决定是否放开 | main 的已确认状态；避免导出后的数据被改 |
| A5 | 导出只有 XLSX；导出文件 24 小时后失效，需要时重新生成；下载凭证 60 秒有效、只能本人使用 | PRD §4.4；main 的做法 |
| A6 | 通用结果的结构为"若干组表头键值 + 若干张明细表"，与 PRD 的自由格式结构相同 | 以后做自由格式时可以沿用 |
| A7 | 一个任务最多尝试 5 次模板转换（含换模板），超过后只能删除结果后重新识别 | main 的 `TEMPLATE_MAX_MAPPINGS_PER_JOB` |
| A8 | 防重复标识按租户唯一（ADR-009 §3 第 5 条：main 为全系统唯一） | 租户之间不应互相影响 |
| A9 | "由谁创建"一栏：游客期间为空，只记录所属的游客租户；注册归集后改为该用户 | ADR-009 §3 第 3 条 |
| A10 | 识别进程与提醒进程一样，作为 compose 中的独立服务运行，可以单独停用 | ADR-009 §1 C 类：不在 Web 进程内跑 worker |
| A11 | 结果页与历史中显示的时间按泰国时间；金额与数字按十进制字符串保存，不经浮点 | main 的做法；NFR-I18N-002 |
