## Why

B-2c 已经有了套餐、订阅、有效期和扫描次数的计量，但用户还不知道"快用完了""快到期了"或"组织的免费额度快过期了"。到期即停之后才发现不能识别，会直接打断工作。PRD §4.9 要求所有档位都有用量提醒与到期提醒。负责人 2026-11-05 把这部分从 B-2c 拆出，作为 B-2d（ADR-006 §7）。

本 change 同时修复 B-2c 最终审查留下的 Minor（负责人 2026-11-05 同意）。其中"上线前的用户与组织补发免费额度"一项，负责人决定不处理，实际修 7 个。

## What Changes

- **到期提醒**（改写 EPIC-06 的 FR-SYS-018）：
  - 在租户的订阅到期前 7 天、3 天、1 天、到期当天、到期后第 1 天各提醒一次，按泰国日期判定。
  - 订阅已续上（下一段订阅紧接或重叠）时，不按旧的结束时间提醒。
  - 同一到期时间、同一节点只提醒一次；错过的节点不补发。
- **用量提醒**（新 FR-SYS-035）：
  - 当月剩余扫描配额不足当月配额的 20% 时提醒一次。
  - 月末前 3 天如仍有剩余配额，再提醒一次。
  - 只按月扫描配额计算，不含免费额度；同一自然月同一节点只提醒一次。
- **组织免费额度的到期提醒**（新 FR-SYS-038；负责人 2026-11-05 要求）：
  - 组织的免费额度到期前 7 天、3 天、1 天、到期当天各提醒一次，只在余量大于 0 时发送。
  - 同一份免费额度、同一节点只提醒一次；错过的节点不补发。
  - 个人租户的免费额度不过期，不提醒。
- **提醒的收件人与投递**（新 FR-SYS-037）：
  - 收件人：组织发给 owner，个人租户发给本人；游客临时租户不提醒，没有有效订阅的组织也不提醒。
  - 渠道：每次提醒都生成一条站内通知；收件人已注册且有邮箱时，再发一封邮件。
  - 邮件发送失败不影响站内通知。
  - 系统至少每 30 分钟检查一次（负责人 2026-11-05：定时检查，最多晚 30 分钟）。
  - LINE OA 消息留出渠道，本 change 不发送。
- **通知中心**（新 FR-SYS-036；原 FR-SYS-018 的后半部分）：
  - 已登录用户可以按时间倒序分页查看自己的通知，以及未读数。
  - 可以把指定的通知或全部通知标记为已读。
  - 通知只有已读、未读两种状态；用户不能删除通知（负责人 2026-11-05）。
- **B-2c 遗留的 7 个 Minor：** 在 plan 内处理，都不改变已确认的 SHALL。
  1. 退还扫描次数时检查预占所属的租户；
  2. admin 直接设定认证状态时关闭待审批申请，这一步写入操作日志，原因不再固定为英文；
  3. 日期接近 9999 年时，返回 400，不再是 500；
  4. 月份的加减按泰国时区计算；
  5. admin 查询不存在的租户的订阅或预占时返回 404；
  6. 没有有效订阅时，用量查询不显示尚未开始的有效期；
  7. 需求索引中身份类需求的来源与行序；PRD 补写同档续费顺延的规则。
- **文档同步：**
  - PRD §4.9：到期后的提醒日、月末前 3 天的日期、游客不提醒、定时检查；
  - `Glossary.md`：用量提醒、到期提醒、站内通知、通知中心；
  - `Data-Model.md`：`DM-Notification`、`DM-Reminder`；
  - EPIC-06：FR-SYS-018 标记已迁移；
  - `Requirements-Index.md`；
  - ADR-006 §7：B-2d 的状态。

## Capabilities

### New Capabilities

- `notifications`：用量提醒、到期提醒、组织免费额度的到期提醒、提醒的收件人与投递（站内通知与邮件）、通知中心。
  - 沿用 EPIC-06 的 `FR-SYS-018` 编号，按 PRD v3.5 与本 change 的决定改写，只保留到期提醒；通知中心改为 `FR-SYS-036`。验收标准重新编号。
  - 新编 `FR-SYS-035`（用量提醒）、`FR-SYS-036`（通知中心）、`FR-SYS-037`（提醒的收件人与投递）、`FR-SYS-038`（组织免费额度的到期提醒）。

### Modified Capabilities

无。7 个 Minor 都不改变 `billing`、`tenancy` 已确认的 SHALL。

## Non-goals

- LINE OA 消息：等 OA 准备好后接入。本 change 只留出发送渠道。
- 短信与手机号验证：随短信平台接入（NFR-SEC-011）。
- 审批结果、邀请等其他类型的通知（负责人 2026-11-05：只做提醒；通知类型可扩展）。
- 上线前已有的用户与组织补发免费额度（负责人 2026-11-05：不处理）。
- 运营界面：admin 不能在后台编辑提醒内容、补发提醒或查看发送统计。
- 通知的删除与过期清理（负责人 2026-11-05：用户侧只显示已读或未读，不提供删除）。
- 任何前端页面（B-5）。

## Decisions（负责人确认，2026-11-05）

| # | 问题 | 结论 |
|---|------|------|
| D1 | 通知范围 | 只做提醒（用量、订阅到期、组织免费额度到期）；通知类型可扩展，以后再加 |
| D2 | 用量提醒的时机 | 定时检查，最多晚 30 分钟；与识别流程（B-3）互不依赖 |
| D3 | "到期后"一次 | 到期后第 1 天（泰国日期）发送；这一天没有发出就不补发，与其他节点一致 |
| D4 | 游客 | 游客临时租户不提醒 |
| D5 | 渠道 | 站内通知与邮件；LINE OA 消息留出渠道，以后接入（B-2c 的 D4） |
| D6 | B-2c 遗留 | Minor 在本 change 中修复；上线前的用户与组织不补发免费额度 |
| D7 | 通知的删除 | 用户侧不删除通知，只显示已读或未读；通知全部保留 |
| D8 | 组织免费额度到期 | 需要提醒 |

## 待负责人确认的假设

| # | 假设 | 理由 |
|---|------|------|
| A1 | 租户的"到期时间"是从现在起连续有效的订阅最终结束的时间：多段订阅首尾相接或重叠时，取最后一段的结束时间 | B-2c 允许同档顺延与改档后重叠；续上了就不应收到"即将到期" |
| A2 | "月末前 3 天"是本月最后一天往前数 3 天的那一天（例如 1 月 28 日、2 月 25 日或 26 日）；当天剩余次数大于 0 才提醒 | 与"到期前 3 天"的数法一致 |
| A3 | 用量提醒的 20% 按检查当时的档位与配额计算；本月已经发过的，月中改档后不再发 | 同一自然月同一节点只发一次 |
| A4 | 没有有效订阅时不发用量提醒；到期提醒已经覆盖这种情况 | 订阅到期后月配额为 0，用量提醒没有意义 |
| A5 | 收件人在发送时确定：组织转让 owner 后，之后的提醒发给新 owner；已经发出的通知仍留在原收件人的通知中心 | 通知属于用户，不属于租户 |
| A6 | 邮件只尝试发送一次，失败不重试；结果可以追溯 | PRD 没有要求重试；站内通知已保证收到 |
| A7 | 邮件使用英文，与现有验证码邮件一致；站内通知存类型与数据（租户、节点、档位、到期时间、剩余次数），文字由前端按语言显示 | 前端将支持多语言 |
| A8 | 系统发送提醒与用户标记已读都不写操作日志；提醒的发送有可追溯的记录（租户、节点、收件人、时间、邮件结果） | 标记已读只改变本人的阅读状态；提醒由系统定时产生，数量多 |
| A9 | 游客调用通知中心返回 401 | 游客不提醒，与游客提交续费申请返回 401 一致 |
| A10 | 组织免费额度的到期提醒节点为到期前 7 天、3 天、1 天与到期当天，与订阅的到期提醒相同但没有"到期后"；只在余量大于 0 时发送；组织是否有有效订阅都照常提醒 | 过期后额度作废，"到期后"的提醒没有用处；有余量才值得提醒 |
| A11 | 运营方可以用配置开关停用提醒的发送；停用期间错过的节点不补发 | 测试与故障时需要临时关闭 |
