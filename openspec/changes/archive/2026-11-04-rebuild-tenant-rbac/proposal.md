## Why

B-2a 已经建立了"每个用户有一个个人租户、每个游客有一个临时租户"。但目前还不能多人协作：不能建组织，不能邀请成员，也不能按角色区分权限。B-3（上传与 OCR，由同事负责）需要先知道"当前用户在哪个租户、能做什么、能看到哪些单据"，所以 B-2b 要先把租户访问规则和权限点定下来（ADR-006 §7 B-2b；ADR-009 §6）。

负责人 2026-11-04 改变了 PRD v3 §4.9 的租户模型：

- **不再有"原地升级"。** 每个用户永久拥有一个个人租户，个人租户中的数据永远留在个人租户，不会迁到组织。
- **"团队租户"改称"组织"（organization）。** 用户提交组织资料、由平台 admin 审批通过后，组织才成立。一个用户可以属于多个组织。组织可以是几个人的松散小组，也可以是正式企业。
- **企业认证保留为组织的可选认证，** 通过后将来解锁额外功能，具体功能以后再设计。
- **每个组织成立时获赠一次性免费额度，1 个月内有效。** 过期或用完后，需线下付费，由 admin 开通套餐。

同时，本 change 修复 B-2a 与 harden-identity 最终审查留下的 9 个 Minor（负责人 2026-11-04 决定）。

## What Changes

- **组织的申请与审批：**
  - 已注册用户填写组织资料提交建组织申请：名称与联系电话必填，地址选填；执照照片等 B-3 的文件上传完成后再补。
  - 平台 admin 批准后组织成立，申请人成为 owner；admin 也可以驳回并填写原因。
- **平台 admin 管理组织：** 通过 admin 后台接口审批申请、查看组织、修改组织资料、停用与恢复组织。
- **租户访问规则（供 B-3 及以后使用）：**
  - 每个请求作用于一个租户，不指定时为本人的个人租户；
  - 个人租户的数据只有本人可见；
  - 组织的数据只对有效成员开放，且受权限点约束：没有"数据浏览"权限的成员只能看到本人提交的数据；
  - 非成员访问组织返回"不存在"。
- **角色与权限点：**
  - 权限点按 PRD §4.9 的 13 项；
  - 每个组织有 owner 与一个默认角色，owner 可以自定义角色；
  - 每个成员只有一个角色。
- **成员邀请：**
  - 持有"成员管理"权限的成员生成一次性邀请链接，7 天有效，可撤销；
  - 接受者须是已注册用户；
  - 未被接受的邀请计入成员人数上限。
- **成员人数上限：** 付费前（免费额度期间）默认 2 人，由平台 admin 配置；开通套餐后按套餐计算（B-2c）。
- **成员移除与退出、owner 转让：** 可以移除成员，成员也可以自行退出；owner 不能被移除，可以把 owner 转让给其他成员，转让后才能退出。
- **企业认证：**
  - 组织的 owner 或持有"企业认证申请"权限的成员提交认证资料：法定名称、税号、注册地址；
  - admin 审批，或在后台直接开通；
  - 组织获得"已认证"标记。
- **操作日志：** 以上每个改变状态的操作都写入 B-2a 的操作日志（FR-SYS-003）。
- **遗留的 9 个 Minor：** 在 plan 内处理，都不改变已确认的 SHALL：
  1. 游客限频的内存开销；IPv6 按 /64 计算；
  2. 中继或策略类拒收不再报成 `email_rejected`；
  3. 收件阶段的 4xx 按临时错误重试；
  4. 更新过时的初始化脚本；
  5. `.env` 中带引号的口令；
  6. 接口测试改用应用账号运行；
  7. 补充 0003 回退的说明；
  8. 用户名规范化在 Python 与 SQL 中保持一致；
  9. 收回应用账号对迁移版本表的 INSERT 权限。
- **文档同步：** 按本 change 的决定改写下列文档：
  - PRD §4.9、`Glossary.md`：团队租户改为组织、去掉原地升级、组织申请与审批、组织的免费额度；
  - `Data-Model.md`；
  - ADR-006 §7 的 B-2b 与 B-2c 两行；
  - ADR-009 §4 中"一个用户可以拥有多个租户"一行；
  - EPIC-06 中 FR-SYS-002、009、017 标记为已迁移。

## Capabilities

### New Capabilities

- `tenancy`：租户与组织——租户访问规则、组织的申请与审批、平台 admin 管理组织、角色与权限点、成员邀请、成员人数上限、成员移除与退出、owner 转让、企业认证。
  - 沿用 EPIC-06 的 `FR-SYS-002`（RBAC，按 PRD v3 改写为角色与权限点；`FR-SYS-009` 的"可授予复核与报表权限"并入其中）与 `FR-SYS-017`（租户切换与隔离，按新模型改写；原 AC-FR-SYS-017-03"企业单独申请套餐"移到 B-2c）。
  - 新编 `FR-SYS-021` 至 `FR-SYS-029`。

### Modified Capabilities

（无。`identity` 的 SHALL 不变：个人租户、游客临时租户与归集规则保持原样；9 个 Minor 都是已有 SHALL 下的缺陷或实现质量问题。）

## Non-goals

- 组织的套餐、免费额度的数量与扣减、额度过期、成员人数上限中按套餐计算的部分、续费与开通套餐（B-2c）。本 change 只确定：组织成立是 B-2c 发放免费额度的起点；付费前的成员人数上限为一个可配置参数。
- 上传、识别、单据等业务数据（B-3、B-4，由同事负责）。本 change 提供租户访问规则与权限点，各业务能力在自己的 change 中遵守。
- 执照照片与认证材料的上传（B-3 的文件模块完成后补）。
- 企业认证解锁哪些功能（以后设计）。
- 删除组织（D13）。
- 任何前端页面（B-5）。
- 模板管理、报表查看这两个权限点对应的功能（P1）。本 change 只定义这两个权限点本身。

## Decisions（负责人确认，2026-11-04）

| # | 问题 | 结论 |
|---|------|------|
| D1 | 租户模型 | 每个用户永久拥有一个个人租户；用户另外申请建立组织，admin 审批通过后成立；一个用户可以属于多个组织 |
| D2 | 个人数据 | 个人租户中的数据永远属于个人租户，不迁移到组织；不再有原地升级 |
| D3 | 术语 | "团队租户"一律改为"组织"，英文为 organization |
| D4 | 企业认证 | 组织可选的认证，通过后将来解锁额外功能；B-2b 只做申请与审批，结果是"已认证"标记 |
| D5 | 组织的初始额度 | 组织成立时获赠一次性免费额度，1 个月内有效，过期作废；过期或用完后需付费，由 admin 开通套餐（数量与扣减规则在 B-2c） |

| D8 | 付费前的成员人数上限 | 与 Starter 相同，默认 2 人，由 admin 配置 |
| D9 | 邀请方式 | 一次性邀请链接，7 天有效，可撤销；接受者须已注册；一个邀请占一个名额 |
| D10 | 每个成员的角色数 | 只有一个 |
| D11 | 遗留 Minor | B-2a 与 harden-identity 遗留的 9 个 Minor 在本 change 中修复 |
| D12 | owner 转让 | owner 可以在组织内把 owner 身份转让给其他成员（FR-SYS-029） |
| D13 | 删除组织 | 暂不提供；只有 admin 可以停用组织 |
| D14 | 企业认证解锁的功能 | 以后再设计 |

## 待负责人确认的假设

| # | 假设 | 理由 |
|---|------|------|
| A1 | 只有已注册用户能申请建组织；同一用户同一时间最多有一个待审批的建组织申请；一个用户可以申请建多个组织（逐个审批） | 防止重复提交；PRD 没有限制可拥有的组织数量 |
| A2 | 组织资料中名称与联系电话必填，地址选填；名称不超过 128 个字符，联系电话沿用 FR-SYS-015 的手机号格式 | 负责人举例为名称、地址、电话；松散小组可能没有地址 |
| A3 | owner 与持有"成员管理"的成员可以修改组织资料（名称、联系电话、地址），无需重新审批；已认证组织的法定名称与税号只能由 admin 修改 | 组织资料用于显示；认证信息需要审核 |
| A4 | 删除一个正在使用的自定义角色时，持有该角色的成员改为默认角色；默认角色与 owner 不能删除；owner 的权限固定为全部权限点，不可修改 | 避免成员处于"没有角色"的状态 |
| A5 | 持有"角色管理"的成员可以定义角色、分配角色、修改默认角色，但不能修改 owner、不能把自己的角色改成权限更多的角色 | 防止越权给自己加权限 |
| A6 | 停用的组织：成员不能再访问其数据，也不能进行任何操作；数据保留；admin 恢复后一切照旧 | 停用不是删除 |
| A7 | 被移除或退出的成员立即失去访问权；他在组织中提交的数据仍属于该组织 | 数据归属租户，不归属个人 |
| A8 | 访问不是本人成员的组织、或已停用的组织时返回"不存在"（HTTP 404），不透露组织是否存在 | 与 B-2a 的游客数据隔离一致 |
| A9 | 转让后原 owner 留在组织中，持有默认角色；只有 owner 本人可以发起转让，不需要受让人确认 | 原 owner 需要权限时，新 owner 可以再为他分配角色；PRD 未要求受让人同意 |
