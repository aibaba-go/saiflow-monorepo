# Design: verification-detail-sticky-layout

追溯：proposal「What Changes」三条 → specs 两条 MODIFIED requirement → 本设计。不引入规格之外的行为。

## 布局骨架（两页共用）

```
┌────────────────────────────────────────────────────────────┐
│ 操作栏 / 抽屉按钮（横贯全宽，不变）                              │
├──────────────┬─────────────────────────────────────────────┤
│  原图 Card    │  头部字段区（核验页：可编辑 FieldRow；          │
│  Col span=6  │  预览页：只读字段行）                           │
│  position:   ├─────────────────────────────────────────────┤
│  sticky      │  行项目表（Col span=18）                       │
│  top: 80px   │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

## 决策

### ADR-003：核验/预览视图采用「sticky 左图 + 右侧两块」骨架

- **背景**：行项目表原先在页面底部全宽渲染，核对行项目时原图滚出视野；三候选方案（表上移全宽 / sticky 左图 / 表并入左栏）中，表并入左栏在 span 10 宽度下 8 列不可用，表上移不解决原图同屏问题。
- **决策**：左栏原图 Col span=6、`position: sticky; top: 80px`（antd Header 64px + 16px 间距）；右栏 Col span=18，上部头部字段、下部行项目表。行项目表保留全部 8 列，`size="small"` 不变。
- **后果**：行项目可用宽度由 24 栅格减至 18 栅格，在 1280px 及以上视口不换行（Prototype 仅针对 PC，不做响应式）；两页共用同一骨架，行为一致。

## 明确数值

- 左栏：`xs=24 lg=6`；右栏：`xs=24 lg=18`（窄视口退化为上下堆叠，原型以 PC 为主，仅保底不破版）。
- sticky：`top: 80px`，`alignSelf: flex-start`（防止 sticky 在 stretch 布局下失效）。
- 行项目表列定义由核验页抽出为共享常量（`lineItemColumns(t)`），预览页只读复用，避免两处漂移。

## 影响面

- `VerificationPage.tsx`：仅详情布局段（Row/Col/样式），FieldRow、门控、状态机逻辑零改动。
- `ArchiveBrowserPage.tsx`：预览布局段重构 + 新增只读行项目表（数据源已有 `storeState.line_items`，过滤 `document_id` 即可）。
- 测试：现有用例按文本/角色定位不受影响；新增 2 条布局断言（核验视图滚动后原图可见性用 CSS sticky 无法在 jsdom 断言，改为断言行项目与原图同属一个 Row 容器内 + 预览页展示行项目数据）。
