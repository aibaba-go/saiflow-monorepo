# 本地隔离开发环境

## Why
负责人于 2026-11-09 要求完成本地功能升级环境，跳过 LINE 联合登录，其余业务保留，且不得与线上环境混用。当前服务没有开发登录开关；恢复的测试服务器数据库包含业务数据，现有集成测试会重置角色和清空表，不能直接运行。

## What Changes
- 增加默认关闭、仅本地且明确配置的开发登录，使用固定独立开发身份，沿用真实会话、租户、权限、版本与审计服务，不模拟业务成功。
- 独立开发与一次性自动化测试数据，测试配置失败关闭；不借用线上 GCS、OCR、LLM、SMTP 凭据。
- 提供可重复启动入口、环境模板和配置检查；明确真实第三方服务未配置时的不可用状态。

## Capabilities
### New Capabilities
- `local-development`：NFR-DEV-001 本地开发隔离、NFR-DEV-002 开发登录边界、NFR-DEV-003 自动化测试数据保护。

## Impact
后端 Settings、LINE 登录接入、原生 CLI，两个客户前端的 config 与启动/登录入口，独立开发脚本和测试防护。遵循 STD-005、STD-006、NFR-SEC-002/003/009/012；不改变正常 LINE 登录契约，不修改旧迁移。

## Non-goals
不部署线上、不提交 Git、不修改线上或恢复库的已有业务数据、不伪造 LINE SDK 分享/相机等原生能力；不把 Mock OCR 或 SMTP 验证报告为真实服务验收。缺少独立第三方测试凭据时保留错误/未配置提示并记录验证缺口。

## 授权与交接
本次方案按负责人最新“无需确认、自主实现并全面测试”的明确授权推进，不追认此前草案的逐项历史确认。实施任务唯一来源为 [plan.md](plan.md)，测试证据写 verification.md。仓库原生工作流不用通用 apply/design/tasks，不修改工作流配置绕过其状态。
