# Proposal：PC 核验页普通字段增行与小程序字段展示

## Why

用户于 2026-11-09 要求截图中 Document 等普通字段分组像明细表一样可增加行。当前 PC 核验页仅在通用结果中提供新增字段入口，模板结果只能编辑预定义字段和增删明细行，无法补录模板未覆盖的信息。负责人随后确认：PC 已保存的额外字段也须在 LINE 小程序的结果页、复核详情和最终结果页显示，避免同一单据跨端查看时遗漏信息。

产品诉求来源：[PRD-SaiFlow §3.1 人工确认及修正](../../../docs/10-product/PRD-SaiFlow.md)；约束来源：[NFR-USAB-003/004、NFR-I18N-003](../../../docs/20-requirements/non-functional/NFR.md)。模板结果新增表头字段不是既有行为，须经本变更的 delta spec 确认，不将其冒充为已有 AC 的小修。

## What Changes

- 变更分级：M；属于现有 P0 核验流程的行为补充，不引入新实体或接口。当前仅为待负责人确认的需求草案。
- 按截图将“普通字段增加行”暂拟为：在已有分组内新增一条自定义“字段名＋字段值”，不是复制整组 Document，也不是同一个字段的多个值。
- PC 模板结果的已有普通字段分组提供“新增字段”入口；名称必填、去除首尾空白，同组内不能与当前数据（含未保存草稿）的字段或模板字段、表格的键冲突。
- 模板字段仍按模板顺序与语言显示；额外字段显示在所属分组的普通字段末尾，使用录入的名称，支持修改值与删除，不允许删除模板定义字段。
- 新字段只修改当前单据的草稿；保存、版本冲突、未保存离开提示、确认门控和确认后锁定沿用原规则，不修改共享文档格式模板。

### LINE 小程序展示范围（负责人已确认）

- 待核验、被退回的结果页：显示 PC 已保存的额外字段，有既有编辑权限且结果未锁定时可以修改字段值并保存；本轮不新增小程序模板额外字段的新增或删除入口。通用结果既有的增删字段能力不变。
- 一级、二级复核详情：显示所确认版本中的额外字段，只读。
- 待复核、已确认的最终结果页：完整显示所确认版本中的额外字段，只读，不因展示额外字段而解锁结果。
- 额外字段位于所属分组（如 Document）的普通字段末尾，不改变模板字段顺序。名称与值原样显示，不自动翻译，不赋予模板未定义的类型转换或必填规则，不修改模板定义。
- PC 未保存的字段不会跨端显示；保存成功后，小程序重新读取结果时显示相应版本的数据，不承诺未重新读取时自动实时同步。
- 首页和历史列表不展开额外字段；不改变原有可见范围或访问权限。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `results`：修改 FR-VERIFY-015，明确模板结果中额外表头字段的草稿增删和保存保留规则。
- `web-pc`：修改 FR-SYS-129，补充模板分组新增字段入口、额外字段显示和字段名校验的 AC。
- `line-mini`：补充 FR-SYS-105 的额外字段显示与修改值规则、FR-SYS-107 的最终结果只读展示、FR-SYS-120 的复核详情只读展示及对应 AC，详见 [line-mini delta spec](specs/line-mini/spec.md)。

## Impact

- UI 主要涉及 `apps/web-pc/src/ocr/EditableResult.tsx`；既有 AddField 可作为入口基础，但模板分支只遍历模板定义，必须补充已保存额外字段的显示。
- 测试涉及 `apps/web-pc/src/ocr/ocr.test.tsx` 及核验页保存、重新加载、离开提示的测试。
- 小程序主要涉及共享的 `StructuredDataView.tsx`，由 `ResultPage.tsx`、`FinalResultPage.tsx` 和 `ReviewDetailPage.tsx` 使用；现有模板视图只遍历模板定义，须补充对应版本已有额外字段的显示，同时区分可编辑值与只读展示，不能意外开放模板额外字段的删除入口。
- 小程序验收须覆盖 PC 保存后重新读取可见、待核验修改值后保存可见、两级复核与最终结果只读、三语下字段名和值原样显示，以及不出现模板额外字段新增或删除入口。可扩展既有 `result.test.tsx`、`final.test.tsx` 和复核测试。
- 后端 `result_service.save` 调用 `normalize.fill_structure`，后者已保留模板外键；集成测试已有保存额外键的断言。预期无需迁移或新增 API，但仍须在实施验证中覆盖新增、删除与版本规则，不把代码阅读当作测试通过。
- 验证只使用 mock 与隔离测试数据库；不得将已恢复的共享 `saiflow` 库配置为 `TEST_DB_*`，集成 fixture 会清空业务表。

## Non-goals

- 不新增分组、表格或表格列，不复制整组字段，不让同名字段变成多值。
- 不修改模板管理、OCR/LLM 转换、权限体系、生产配置或本地开发登录。
- 不在小程序中新增模板额外字段的新增或删除入口，不改变通用结果既有的增删字段能力。
- 不修改 PC 单据详情或 Excel 导出版式。已核实当前模板 XLSX 导出不展示额外字段；本次小程序页面可见不代表导出文件包含这些字段。
- 不修改首页或历史列表的展示，不承诺跨端实时同步。
- 不提交、部署或归档未经确认和验证的变更。

## Confirmation / Review Points

1. 负责人于 2026-11-09 同意上述小程序展示范围：待核验和退回结果可按原权限修改值；复核详情、待复核及已确认最终结果只读；不增加小程序模板额外字段新增或删除入口；Excel 导出不纳入本次范围。
2. PC 普通字段增行仍按现有草案的自定义字段名＋值语义描述；本次确认不代表原有 proposal 与 delta spec 的全部 SHALL 和 AC 已逐条确认。若实际需要重复整组或同字段多值，应调整规格后再编码。
3. PC 单据详情保持本次非目标，额外字段在该路径的展示不作新增承诺。
