## Why

B-2b 已经让用户可以建组织、邀请成员、按权限点协作，但现在还没有"能扫多少"的概念：没有套餐，没有订阅和有效期，没有免费额度，也没有扫描次数的计量。B-3（上传与 OCR，由同事负责）在新建识别任务前，需要一个确定的接口来判断"这个租户还能不能扫、扣多少"。B-2a 的决定 D3 规定由 B-2c 制定扣减规则与接口，B-3 识别时调用（ADR-006 §7；ADR-009 §6）。

负责人 2026-11-05 决定把原 B-2c 拆成两个 change：

| change | 范围 |
|---|---|
| **B-2c `rebuild-plans-metering`**（本 change） | 套餐目录、订阅与有效期、免费额度、扫描次数的预占与退还（B-3 调用）、续费与开通申请、按套餐的成员人数上限；B-2b 留下的 10 个 Minor |
| **B-2d `rebuild-notifications`** | 用量提醒、到期提醒、通知中心；渠道为站内通知与邮件，LINE OA 消息另行接入 |

同一天负责人还决定：B-2b 留下的 10 个 Minor 在本 change 修复；已通过企业认证的组织不能再提交认证申请；B-2a 迁移过的身份类需求在本 change 的文档同步中补标"已迁移"。

## What Changes

- **套餐目录：**
  - 四档套餐：Kinder、Starter、Intermediate、Advance。
  - 每档有每月扫描配额和成员人数上限，平台 admin 可以在后台修改，改动对已有订阅立即生效。
  - Kinder 的成员人数上限固定为 1。
  - Kinder 只用于个人租户与游客临时租户；Starter 及以上只用于组织。
- **订阅与有效期：**
  - 每个租户最多有一个当前订阅：档位、按月或按年、开始与结束时间。
  - 个人租户与游客临时租户在建立时自动开通一个月 Kinder。
  - 组织成立时没有订阅，由 admin 在线下收款后开通。
  - 订阅到期后不能新建识别，已有数据照常可以读取。
- **免费额度：**
  - 用户注册时，其个人租户获赠一次（默认 100 次），不过期，但订阅到期期间暂停使用。
  - 组织成立时获赠一次（默认 100 次），自成立起 1 个月内有效，过期作废。
  - 两个默认值都由平台 admin 配置。
- **扫描次数的预占与退还（供 B-3 调用）：**
  - 每识别一页计一次。
  - 新建识别时按页数一次性预占，先用免费额度，不够的部分再用当月扫描配额。
  - 余量不足就整份拒绝，并告知还剩几次。
  - 识别失败或被取消时，退还预占的次数。
  - 月扫描配额按泰国时区的自然月计算，月初重新计数，不结转；年付套餐每月按档位重新计数。
- **用量查询：** 租户成员可以查看当前档位、有效期、本月已用与剩余次数，以及免费额度余量与到期时间。
- **续费与开通申请：**
  - 申请人：个人租户为本人；组织为 owner 或持有"套餐申请"权限点的成员。
  - 申请内容：目标档位、按月或按年、备注。
  - 平台 admin 线下收款后批准，并设定有效期；也可以驳回并填写原因，或不经申请直接为租户设定订阅。
  - 档位规则：同档可以续；订阅有效期内不能降档；到期后可以选择任何档位，但组织最低为 Starter，个人租户只有 Kinder。
- **按套餐的成员人数上限：** 组织有有效订阅时按其档位计算，没有时按 B-2b 的"开通套餐前上限"（默认 2）计算。这一条修改 `tenancy` 的 FR-SYS-025。
- **企业认证：** 已认证的组织不能再提交认证申请，返回 409。这一条修改 `tenancy` 的 FR-SYS-027。
- **操作日志：** 以上每个改变状态的操作都写入操作日志。
- **B-2b 遗留的 10 个 Minor：** 在 plan 内处理，都不改变已确认的 SHALL。
  1. 路径与请求体中的 ID 不是数字或超出范围时，返回 404 或 400，不再是 422 或 500；
  2. 拿锁后重新确认操作者的权限；
  3. 删除角色与分配角色同时发生时不再返回 500；
  4. 企业认证的提交与批准按同一顺序加锁；
  5. admin 直接设定认证状态时，同时处理待审批的申请；
  6. 没有改动的组织资料修改不写日志；
  7. 补充 0004 回退的说明；
  8. 设置接口与认证设定接口的请求体统一校验；
  9. 补齐接口的响应类型；
  10. 已认证组织再次提交认证返回 409（见上，SHALL 级）。
- **文档同步：**
  - PRD §4.9 与 ADR-006 §7：B-2c 与 B-2d 两行、LINE OA 延后；
  - `Glossary.md`：组织的免费额度、预占；
  - `Data-Model.md`：`DM-Plan`、`DM-Subscription`、`DM-FreeQuota`、`DM-Application`；
  - EPIC-06：FR-SYS-012、013 标记已迁移，并补标 B-2a 的 FR-SYS-001、003、010、014、015、016、019、020；
  - `Requirements-Index.md`。

## Capabilities

### New Capabilities

- `billing`：套餐目录、订阅与有效期、免费额度、扫描次数的预占与退还、用量查询、续费与开通申请，以及这些操作的操作日志。
  - 沿用 EPIC-06 的 `FR-SYS-012`（订阅与到期即停）与 `FR-SYS-013`（扫描计量）编号，按 PRD v3.4 与本 change 的决定改写，验收标准重新编号。
  - 新编 `FR-SYS-030` 至 `FR-SYS-034`。

### Modified Capabilities

- `tenancy`：修改 FR-SYS-025（开通套餐后按档位计算成员人数上限）与 FR-SYS-027（已认证的组织不能再提交认证申请）。

## Non-goals

- 用量提醒、到期提醒、站内通知与通知中心、邮件通知（B-2d）；LINE OA 消息（B-2d 之后接入）；短信（随短信平台）。
- 在线支付、价格与自动续费：付款一律线下进行，价格由 GTM 维护。
- 识别任务本身（B-3）。本 change 提供预占与退还接口；接入时间点由 B-3 实现。
- 任何前端页面（B-5）。
- 套餐差异中的模板、看板、对接功能（PRD §4.9"其他档位差异"，V1.0 不按档位实现）。

## 待负责人确认的假设

| # | 假设 | 理由 |
|---|------|------|
| A1 | 订阅保留历史：每次开通、续费或改档都留下一段记录（档位、开始、结束、来源），当前订阅是其中正在生效或最近的一段 | ADR-009 留给 B-2c 的问题；有历史才能核对线下收款 |
| A2 | 个人租户与游客临时租户的一个月 Kinder 自租户建立时起算；B-2c 上线时已有的个人租户与游客临时租户各补开通一个月，从上线时起算 | dev 环境的数据没有价值，从上线时起算最简单 |
| A3 | 免费额度与月扫描配额可以拼在一起用：例如剩余 5 次免费额度、本月还剩 100 次时，一份 10 页的单据先用 5 次免费额度，再用 5 次月配额 | PRD："先扣免费额度，用完后再扣月扫描配额" |
| A4 | 预占计入预占发生的那个自然月；如果跨月才退还，退还给原来的那个月，不补给新的月份 | 月配额不结转；也避免跨月"多出"次数 |
| A5 | 平台 admin 设定或批准订阅时，默认有效期为：同档且仍在有效期内时，从当前结束时间往后顺延；否则从设定时起算；时长为一个月或一年；admin 可以改成任意的开始与结束日期 | PRD："自修改时起算"；同档续费不应吃掉剩余天数 |
| A6 | 同一租户同一时间最多一条待审批的续费或开通申请 | 与建组织申请、认证申请一致 |
| A7 | 组织的任何成员都能查看本组织的档位、有效期与剩余次数；只有 owner 与"套餐申请"权限的持有者可以提交申请 | 成员扫描前需要知道还能不能扫 |
| A8 | 游客临时租户的数据归集到个人租户时，游客的订阅与已用次数不转移；个人租户按自己的订阅与额度计算 | 游客试用期与正式账号分开计算 |
| A9 | 组织的订阅到期后，成员人数上限回到"开通套餐前上限"，现有成员保留，只是不能再邀请 | 与 FR-SYS-025 调低上限的规则一致 |
