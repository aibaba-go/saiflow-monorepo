## Why

B-1 已上线可部署的骨架，但新系统还没有"用户是谁"的概念：不能登录、不能试用、不能注册。后续的租户、套餐、上传与识别都要先知道当前用户和他的租户，所以 B-2 的第一步先建立身份（ADR-006 §7 B-2；PRD §4.9"用户与租户""注册与登录"）。

负责人 2026-11-03 决定把 B-2 拆成三个依次完成的 change：

| 顺序 | change | 范围 |
|------|--------|------|
| B-2a | `rebuild-identity`（本 change） | LINE 登录、游客会话与数据归集、注册与邮箱验证、个人资料、admin 后台账号、操作日志 |
| B-2b | `rebuild-tenant-rbac` | 个人租户与团队租户、原地升级、成员邀请、角色与权限点、租户切换、企业认证 |
| B-2c | `rebuild-plans-metering` | 订阅与四档套餐、免费额度、月扫描配额与扣减接口、续费与升级申请、用量与到期提醒、通知渠道（站内、LINE OA、邮件） |

三个 change 都只做后端接口（负责人决定），页面在 B-5 完成。

## What Changes

- **LINE 登录**：LINE 小程序与 web-pc 企业版都用 LINE 登录；后端校验 LINE 身份，按 LINE 身份 ID 找到用户，首次登录时创建用户与其个人租户。登录 30 天不使用才失效；可以退出。
- **游客**：未登录进入时建立游客会话与临时租户；游客数据只有本人可见。游客随后用 LINE 登录（新用户或已注册用户都一样）时，临时租户名下的全部数据归入该用户的个人租户，游客会话随即失效。
- **注册**：已登录但未注册的用户提交注册：邮箱必填且须经验证码验证，手机号选填，昵称必填，同时记录 LINE 身份 ID。
- **邮箱验证码**：注册与更换邮箱共用；发信走经加密的 SMTP，临时性错误按 D5 重试。
- **个人资料**：修改昵称、手机号；更换邮箱（验证新邮箱）。头像只使用 LINE 头像，不提供上传。
- **admin 后台账号**：与客户账号完全隔离；用户名 + 口令登录；账号只能在服务器上用命令创建、停用、重设口令；连续 5 次输错锁定 15 分钟。
- **操作日志**：只能追加，记录身份相关的每个改变状态的操作（谁、何时、对什么、结果）；后续 change 沿用同一套日志。
- **文档同步**：ADR-006 §7 的 B-2 行拆成 B-2a / B-2b / B-2c。

## Capabilities

### New Capabilities

- `identity`：用户身份与会话——LINE 登录与退出、游客会话与数据归集、注册与邮箱验证、个人资料修改、admin 后台独立账号，以及身份相关操作的操作日志。需求沿用 EPIC-06 的 `FR-SYS-*` 编号（按 PRD v3 改写），admin 账号新编 `FR-SYS-019`、邮箱验证码新编 `FR-SYS-020`。

### Modified Capabilities

（无。`platform-baseline` 不变：本 change 的接口沿用其统一错误响应与配置加载规则。）

## Non-goals

- 租户成员、邀请、角色与权限点、团队租户升级、租户切换、企业认证（B-2b）。本 change 只建立"每个用户有一个个人租户、每个游客有一个临时租户"这一最小事实。
- 订阅、套餐、免费额度、月扫描配额、续费与升级申请、用量与到期提醒、站内通知与 LINE OA 消息（B-2c）。游客与个人租户自动开通一个月 Kinder 也在 B-2c。
- 任何前端页面（B-5）；"结果页确认前要求注册"的门禁（FR-SYS-011，随核验在 B-4）。
- 头像上传；短信 OTP 与手机号验证（随短信平台接入，NFR-SEC-011）；Google / Facebook 登录；登录失败锁定客户账号（FR-SYS-007，P1）。
- 账号注销与个人数据删除、游客数据的保留期限与自动清理（并入 PRD OQ-4，投产前决定）。
- 旧系统用户与数据的迁移。

| # | 问题 | 结论 |
|---|------|------|
| D1 | B-2 怎么拆 | 拆成 B-2a / B-2b / B-2c 三个 change（见 Why） |
| D2 | 前端范围 | B-2 只做后端接口，页面在 B-5 |
| D3 | 计量边界 | B-2c 定扣减规则与接口，B-3 识别时调用（记录于此，供 B-2c 引用） |

| D5 | 客户登录有效期 | 连续 30 天未使用才失效，每次使用顺延 |
| D6 | 个人资料 | 可改昵称、手机号、换邮箱；头像只用 LINE 头像，不做上传 |
| D7 | admin 账号 | 只能在服务器上用命令创建、停用、重设口令；口令至少 12 位；连续 5 次输错锁定 15 分钟 |
| D8 | 邮箱验证码 | 6 位数字，10 分钟有效，60 秒内不能重发，同一个码输错 5 次作废 |
| D9 | 发信 | 经加密的 SMTP，地址与凭据在服务器环境变量文件；dev 环境先用现有 Gmail 账号，投产前可换专业发信服务 |
| D10 | 已注册用户以游客身份试用后登录 | 与新注册相同：游客数据归入该用户的个人租户，游客会话失效 |
| D11 | 操作日志 | 在本 change 建立，先记录身份相关操作 |

## 待负责人确认的假设

| # | 假设 | 理由 |
|---|------|------|
| A1 | admin 后台会话连续 30 分钟无操作即失效 | admin 能跨租户修改数据，失效时间应比客户登录短 |
| A2 | 每个邮箱只能属于一个用户；注册或换邮箱时邮箱已被他人使用则拒绝 | 邮箱是关联身份，必须唯一指向一个用户（PRD §4.9） |
| A3 | 操作日志每条记录带上前一条的校验值，可用命令检查是否被篡改 | NFR-SEC-004 要求"仅可追加且经过完整性检查" |
| A4 | LINE 身份校验遇到临时性错误时也按 D5 重试 3 次；仍失败则登录失败，不改用其他登录方式 | D5 适用于所有外部服务 |
