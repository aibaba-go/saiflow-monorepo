# Proposal：LINE 小程序 Home 手动刷新

## Why

用户于 2026-11-09 要求在 LINE 小程序 Home 页面增加刷新按钮。当前首页有用量、待处理、最近任务及通知等读取请求，但没有显式手动刷新入口，用户无法在原地重新获取这些信息。

产品诉求来源：[PRD-SaiFlow §3.1 OCR 与人工核验流程](../../../docs/10-product/PRD-SaiFlow.md)；约束来源：[NFR-USAB-003/004、NFR-I18N-003](../../../docs/20-requirements/non-functional/NFR.md)，以及 [STD-008 界面规范](../../../docs/00-standards/UI-Design-System.md)。

## What Changes

- 变更分级：M；现有 P0 首页能力的行为补充，无新增实体或接口。当前为待负责人确认的需求草案。
- 首页提供可访问的“刷新”按钮，刷新首页可见的服务端数据：当前租户的用量和套餐、本人待处理、最近 10 个任务，以及适用的通知未读数和待复核数量。
- 刷新只重新读取数据，不重新启动 LINE 登录、不整页重载、不创建识别任务、不自动重新上传或重试失败文件，不把通知标为已读。
- 刷新期间显示统一等待状态并禁止重复触发；成功更新对应区域，部分请求失败时保留已有数据并显示本地化提示，可再次刷新。
- 刷新保持当前工作区、上传队列、链接输入和仍存在的待处理记录的勾选；不以此操作复位首页状态。
- 游客和无复核权限的用户不因刷新而访问各自不可用的通知或复核数据；租户切换不串数据。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `line-mini`：修改 FR-SYS-109，补充首页刷新范围、等待与失败反馈、状态保留和租户隔离的 AC。

## Impact

- 主要涉及 `apps/line-mini/src/features/scan/ScanHomePage.tsx`、配套 CSS Modules 和三语资源；按钮预期位于首页头部操作区域，不改原有区块顺序。
- 复用现有 TanStack Query 读取能力：待处理、最近任务、用量、通知未读数、已有待复核摘要。通知未读数属于当前用户，不错误地当作当前租户单独的未读数。
- `ReviewEntry` 的摘要读取由复核权限控制；刷新必须覆盖当前可见的待复核数量，又不能为隐藏入口新增无权限请求。
- `ScanHome` 按租户标识重新挂载是既有切换行为；手动刷新不能通过改变挂载标识或重新加载整页实现。
- 扩展 `apps/line-mini/src/features/scan/home.test.tsx` 等 mock API 测试，验证各项读取更新、连续点击、部分失败、上传与输入保留、游客/权限边界及跨租户响应隔离。
- 无需数据库迁移、API 契约更新或调用真实 OCR、GCS、SMTP；不使用共享恢复库运行会清表的集成 fixture。

## Non-goals

- 不新增自动轮询或下拉刷新，不改变历史页、结果页或 PC 首页。
- 不刷新整个身份启动流程，不重启登录、不自动创建游客、不以刷新恢复或扩大权限。
- 不新增扫描、删除、批量确认、邮件发送等写操作；已有上传的正常完成不视为刷新触发的写操作。
- 不修改本地开发环境、生产服务器、部署配置或 Git 提交。

## Review Points

本草案将“刷新”限定为首页可见数据的原地重新读取。按钮具体尺寸、三语文案与窄屏布局在经确认的 `plan.md` 中按 STD-008 细化；不以规格校验代替负责人确认。
