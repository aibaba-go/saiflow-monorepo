## MODIFIED Requirements

### Requirement: FR-SYS-001 LINE 登录与会话
LINE 小程序与 web-pc 企业版 SHALL 通过以下方式之一建立客户会话：
- LINE 登录；
- 已注册用户的邮箱密码登录（FR-SYS-149）；
- 已注册用户的邮箱验证码登录（FR-SYS-150）；
- 重置密码后的登录（FR-SYS-151）。

新用户 SHALL 只能通过 LINE 登录创建；其他方式 SHALL NOT 创建用户或租户。

**LINE 登录**

- 后端 SHALL 校验 LINE 身份令牌的签发方、受众（配置的 LINE Channel）与有效期，并按其中的 LINE 身份 ID 找到用户。
- 该 LINE 身份 ID 尚无对应用户时，后端 SHALL 创建一个未注册的用户及其个人租户。
- 系统内部 SHALL 以唯一的用户 ID 标识用户；LINE 身份 ID 与邮箱都作为关联身份指向该用户 ID。

**会话**（无论以哪种方式建立）

- 客户会话 SHALL 在连续 30 天未被使用后失效，每次使用顺延。
- 登录请求携带一个有效的客户会话时，该会话 SHALL 在新会话建立时失效；其他设备上的客户会话 SHALL NOT 因此失效。重置密码的例外见 FR-SYS-151。
- 用户 SHALL 可以退出，退出后该会话立即失效。会话已失效、不存在或无法识别时，退出 SHALL 同样返回成功，并 SHALL 清除客户端保存的会话凭据。

**禁止与重试**

- 后端 SHALL NOT 接受任何模拟或开发用身份。
- LINE 校验失败时，后端 SHALL NOT 自动改用其他登录方式。
- LINE 校验遇到临时性错误（超时、对方服务报错、限流）时，后端 SHALL 重试最多 3 次且间隔逐次加长，仍失败则登录失败。

#### Scenario: AC-FR-SYS-001-01 首次登录创建用户与个人租户
- **GIVEN** 一个有效的 LINE 身份令牌，其 LINE 身份 ID 在系统中不存在
- **WHEN** 用该令牌登录
- **THEN** 登录成功，系统创建一个未注册的用户、一个属于该用户的个人租户，并建立客户会话

#### Scenario: AC-FR-SYS-001-02 再次登录找到同一用户
- **GIVEN** 一个 LINE 身份 ID 已对应某个用户
- **WHEN** 分别从 LINE 小程序与 web-pc 企业版用该 LINE 身份登录
- **THEN** 两次登录得到同一个用户 ID，不创建新用户或新的个人租户

#### Scenario: AC-FR-SYS-001-03 无效令牌被拒绝
- **GIVEN** 一个签发方不符、受众不是配置的 LINE Channel、已过期或签名无效的令牌
- **WHEN** 用该令牌登录
- **THEN** 返回 HTTP 401，不创建用户、个人租户或会话

#### Scenario: AC-FR-SYS-001-04 模拟身份被拒绝
- **GIVEN** 登录请求只携带一个开发用或模拟的身份标识，没有有效的 LINE 身份令牌
- **WHEN** 发起登录
- **THEN** 返回 HTTP 400，不查找或创建任何用户、租户或会话

#### Scenario: AC-FR-SYS-001-05 LINE 临时不可用
- **GIVEN** LINE 身份校验连续返回临时性错误
- **WHEN** 发起登录
- **THEN** 后端共重试 3 次且间隔逐次加长，随后返回 HTTP 503，不创建会话

#### Scenario: AC-FR-SYS-001-06 30 天未使用失效
- **GIVEN** 一个客户会话最后一次使用在 30 天以前
- **WHEN** 用该会话调用需要登录的接口
- **THEN** 返回 HTTP 401

#### Scenario: AC-FR-SYS-001-07 使用后顺延
- **GIVEN** 一个客户会话在第 29 天被使用过一次
- **WHEN** 在那次使用后的第 29 天再次使用该会话
- **THEN** 请求成功

#### Scenario: AC-FR-SYS-001-08 退出
- **GIVEN** 一个有效的客户会话
- **WHEN** 用户退出后再用该会话调用需要登录的接口
- **THEN** 退出返回成功，之后的调用返回 HTTP 401

#### Scenario: AC-FR-SYS-001-09 再次登录撤销旧会话
- **GIVEN** 一个用户在设备 A 上有客户会话 S1，在设备 B 上有客户会话 S2
- **WHEN** 在设备 A 上携带 S1 再次登录（用 LINE 或邮箱密码），得到新会话 S3
- **THEN** 用 S1 调用需要登录的接口返回 HTTP 401，用 S2 与 S3 调用都成功

#### Scenario: AC-FR-SYS-001-10 失效的会话退出
- **GIVEN** 一个已失效、已退出或无法识别的客户会话凭据，以及完全不带会话凭据的请求
- **WHEN** 分别请求退出
- **THEN** 都返回成功，响应指示客户端清除会话凭据

#### Scenario: AC-FR-SYS-001-11 不同登录方式得到同一用户
- **GIVEN** 一个已注册用户 U，其 LINE 身份 ID 为 L，邮箱为 E，已设置密码
- **WHEN** 分别用 LINE 身份 L、用 E 加密码、用 E 加邮箱验证码登录
- **THEN** 三次都得到 U 的用户 ID，不创建新用户或新的个人租户

### Requirement: FR-SYS-010 游客会话与数据归集
未登录的访问者 SHALL 可以建立游客会话；建立时系统 SHALL 为其创建一个临时租户。

- **频率限制**：同一来源 IP 地址在任意连续 60 秒内 SHALL 最多建立 30 个游客会话，超出的请求 SHALL 被拒绝且不创建会话或临时租户。
- **可见范围**：游客临时租户中的数据 SHALL 只对该游客本人可见。
- **登录时归集**：游客会话中的访问者随后登录时，系统 SHALL 在同一事务中把该临时租户名下的全部数据归入该用户的个人租户，并使游客会话失效。
  - 适用于任何一种登录方式：LINE 登录、邮箱密码登录、邮箱验证码登录或重置密码后的登录。
  - 无论对应的是新用户还是已有用户都归集。
  - 归集失败时 SHALL 不留下部分归入的数据，也不改变游客会话。
- **游客不可用的接口**：游客 SHALL NOT 使用只对已登录用户开放的接口（个人资料、注册、更换邮箱）。

#### Scenario: AC-FR-SYS-010-01 建立游客会话
- **GIVEN** 一个没有任何会话的访问者
- **WHEN** 请求建立游客会话
- **THEN** 返回成功，系统创建一个游客会话及其临时租户

#### Scenario: AC-FR-SYS-010-02 游客数据只本人可见
- **GIVEN** 两个不同的游客会话 A 与 B，A 的临时租户中有数据
- **WHEN** 用游客会话 B 读取 A 的临时租户中的数据
- **THEN** 返回 HTTP 403 或 404，不返回任何 A 的数据

#### Scenario: AC-FR-SYS-010-03 登录后归集到新用户
- **GIVEN** 一个游客会话，其临时租户中有数据；一个尚无对应用户的 LINE 身份
- **WHEN** 在该游客会话中用该 LINE 身份登录
- **THEN** 原临时租户名下的全部数据都属于新用户的个人租户，原游客会话再使用时返回 HTTP 401

#### Scenario: AC-FR-SYS-010-04 登录后归集到已注册用户
- **GIVEN** 一个已注册用户，其个人租户中已有数据；一个游客会话，其临时租户中有数据
- **WHEN** 在该游客会话中用该已注册用户的 LINE 身份登录
- **THEN** 该用户的个人租户同时含有原有数据与原临时租户的全部数据，原有数据不变，原游客会话失效

#### Scenario: AC-FR-SYS-010-05 归集失败不留下部分结果
- **GIVEN** 一个游客会话，其临时租户中有多条数据，归集过程中发生错误
- **WHEN** 在该游客会话中用 LINE 身份登录
- **THEN** 登录失败，临时租户中的数据全部保持原样，游客会话仍然有效

#### Scenario: AC-FR-SYS-010-06 游客不能使用登录用户的接口
- **GIVEN** 一个游客会话
- **WHEN** 调用修改个人资料、注册或更换邮箱的接口
- **THEN** 返回 HTTP 401，不修改任何数据

#### Scenario: AC-FR-SYS-010-07 游客会话建立频率
- **GIVEN** 同一来源 IP 在最近 60 秒内已建立 30 个游客会话
- **WHEN** 该 IP 再次请求建立游客会话，以及另一个 IP 请求建立游客会话
- **THEN** 前者返回 HTTP 429，不创建会话或临时租户；后者成功；60 秒窗口过去后前者的 IP 可以再次建立

#### Scenario: AC-FR-SYS-010-08 邮箱登录同样归集
- **GIVEN** 一个已注册用户 U（已设置密码）；两个游客会话 G1 与 G2，各自的临时租户中都有数据
- **WHEN** 在 G1 中用 U 的邮箱与密码登录，在 G2 中用 U 的邮箱与邮箱验证码登录
- **THEN** 两个临时租户的数据都归入 U 的个人租户，G1 与 G2 再使用时返回 HTTP 401

### Requirement: FR-SYS-014 注册
已登录但未注册的用户 SHALL 可以提交注册，填写以下内容：

| 字段 | 要求 |
|---|---|
| 邮箱 | 必填，SHALL 已通过本人的"验证邮箱"用途验证码验证（FR-SYS-020） |
| 密码 | 必填，SHALL 符合客户密码规则（FR-SYS-152） |
| 手机号 | 选填 |
| 昵称 | 必填，不超过 128 个字符 |

"确认密码"由页面检查与密码一致（FR-SYS-042），后端只接收密码。

系统 SHALL 在注册时：
- 记录该用户的 LINE 身份 ID、邮箱与（如填写）手机号作为关联身份；
- 只保存密码的强单向哈希；
- 记录注册时间。

预填与覆盖：
- 后端 SHALL 只使用经校验的 LINE 身份令牌中的邮箱作为预填值，SHALL NOT 信任客户端声明的 LINE 邮箱。
- 已注册用户再次提交注册 SHALL 被拒绝。
- 已注册用户再次 LINE 登录 SHALL NOT 用 LINE 资料覆盖其已保存的昵称、邮箱与手机号。

#### Scenario: AC-FR-SYS-014-01 注册成功
- **GIVEN** 一个已登录未注册的用户，已向邮箱 E 发送"验证邮箱"用途的验证码并取得该码
- **WHEN** 提交注册：邮箱 E、该验证码、符合规则的密码 P、昵称、可选的手机号
- **THEN** 注册成功，用户被标记为已注册并记录注册时间，邮箱 E 与手机号成为该用户的关联身份，验证码被消费；之后可以用 E 与 P 登录（FR-SYS-149）

#### Scenario: AC-FR-SYS-014-02 缺少或错误的验证码
- **GIVEN** 一个已登录未注册的用户
- **WHEN** 提交注册时验证码缺失、错误、过期、已使用、不是发给所填邮箱的，或用途不是"验证邮箱"
- **THEN** 返回 HTTP 400 并指出验证码字段，用户保持未注册

#### Scenario: AC-FR-SYS-014-03 必填与格式校验
- **GIVEN** 一个已登录未注册的用户
- **WHEN** 提交注册时出现以下任一情况：
  - 缺少昵称，或昵称超过 128 个字符；
  - 邮箱格式不正确，或手机号格式不正确；
  - 缺少密码，或密码不符合客户密码规则
- **THEN** 返回 HTTP 400 并列出出错的字段，用户保持未注册，验证码不被消费

#### Scenario: AC-FR-SYS-014-04 重复注册
- **GIVEN** 一个已注册的用户
- **WHEN** 再次提交注册
- **THEN** 返回 HTTP 409，已保存的资料不变

#### Scenario: AC-FR-SYS-014-05 邮箱已被他人使用
- **GIVEN** 邮箱 E 已是另一个用户的关联身份
- **WHEN** 一个未注册用户用邮箱 E 提交注册
- **THEN** 返回 HTTP 409，用户保持未注册

#### Scenario: AC-FR-SYS-014-06 再次登录不覆盖资料
- **GIVEN** 一个已注册用户，保存的昵称与 LINE 上的昵称不同
- **WHEN** 该用户再次通过 LINE 登录
- **THEN** 保存的昵称、邮箱与手机号不变

#### Scenario: AC-FR-SYS-014-07 只保存密码哈希
- **GIVEN** 一个用户以密码 P 完成注册
- **WHEN** 检查数据库、接口响应、服务端日志与操作日志
- **THEN** 数据库中只有 P 的单向哈希，任何地方都不出现 P 的明文

### Requirement: FR-SYS-020 邮箱验证码
系统 SHALL 提供以下三种用途的邮箱验证码：

| 用途 | 用于 | 谁可以请求 | 可以发往 |
|---|---|---|---|
| 验证邮箱 | 注册（FR-SYS-014）与更换邮箱（FR-SYS-016） | 已登录的用户 | 任一邮箱 |
| 登录 | 邮箱验证码登录（FR-SYS-150） | 任何访问者，不需要会话 | 已注册用户的邮箱 |
| 重置密码 | 重置密码（FR-SYS-151） | 任何访问者，不需要会话 | 已注册用户的邮箱 |

**发往未注册邮箱**："登录"或"重置密码"用途的请求，所填邮箱不是任何已注册用户的邮箱时，SHALL 返回 HTTP 404、错误码 `email_not_registered` 并指出邮箱字段，不发送邮件。

**验证码本身**

- 验证码 SHALL 为 6 位数字，自成功发送起 10 分钟内有效，只能使用一次。
- 验证码 SHALL 只对其所属用户、该邮箱与该用途有效。"验证邮箱"用途的所属用户是请求者；另外两种用途的所属用户是该邮箱的用户。
- 验证码 SHALL 只在邮件发送成功后才生效。
- 邮件 SHALL 说明验证码的用途。

**重发与作废**

- 同一所属用户在上一次成功发送后 60 秒内再次请求（任何用途） SHALL 被拒绝。
- 为同一所属用户成功发送新码后，该用户的旧码（任何用途） SHALL 作废。
- 同一个码被输错 5 次后 SHALL 作废。

**按来源 IP 限流**：不需要会话的请求 SHALL 与邮箱登录、重置密码共同受来源 IP 频率限制（FR-SYS-157）。

**发信**

- 邮件 SHALL 通过经加密的 SMTP 连接发送。
- 发送遇到临时性错误时，SHALL 重试最多 3 次且间隔逐次加长。
- 仍失败或发信未配置时，SHALL 返回服务不可用，且不产生有效的验证码。
- 邮件服务器以永久性错误拒收时，SHALL 不重试，SHALL 返回请求错误并指出邮箱字段，且不产生有效的验证码。

**不外泄**：验证码 SHALL NOT 出现在接口响应与日志中。

#### Scenario: AC-FR-SYS-020-01 发送成功
- **GIVEN** 一个已登录的用户，发信服务可用
- **WHEN** 请求向邮箱 E 发送"验证邮箱"用途的验证码
- **THEN** 返回成功，邮箱 E 收到一封含 6 位数字验证码的邮件，响应中不含验证码

#### Scenario: AC-FR-SYS-020-02 60 秒内重发
- **GIVEN** 一个用户在 60 秒内已成功发送过一次验证码
- **WHEN** 再次请求发送
- **THEN** 返回 HTTP 429，不发送邮件，原验证码仍然有效

#### Scenario: AC-FR-SYS-020-03 新码使旧码作废
- **GIVEN** 一个用户先后成功发送了两次验证码（间隔超过 60 秒）
- **WHEN** 用第一次的验证码提交
- **THEN** 验证码被判为无效

#### Scenario: AC-FR-SYS-020-04 过期
- **GIVEN** 一个验证码已发送超过 10 分钟
- **WHEN** 用该验证码提交
- **THEN** 验证码被判为无效

#### Scenario: AC-FR-SYS-020-05 输错 5 次作废
- **GIVEN** 一个有效的验证码已被输错 5 次
- **WHEN** 用正确的验证码提交
- **THEN** 验证码被判为无效

#### Scenario: AC-FR-SYS-020-06 发信临时失败
- **GIVEN** SMTP 服务连续返回临时性错误
- **WHEN** 请求发送验证码
- **THEN** 后端共重试 3 次且间隔逐次加长，随后返回 HTTP 503，不产生有效的验证码

#### Scenario: AC-FR-SYS-020-07 发信未配置
- **GIVEN** 服务器上没有配置 SMTP
- **WHEN** 请求发送验证码
- **THEN** 返回 HTTP 503，不产生有效的验证码

#### Scenario: AC-FR-SYS-020-08 验证码不进日志
- **GIVEN** 一次成功的发送与一次失败的提交
- **WHEN** 检查这两次请求产生的服务端日志与操作日志
- **THEN** 其中不出现验证码

#### Scenario: AC-FR-SYS-020-09 邮箱被拒收
- **GIVEN** 邮件服务器对邮箱 E 返回永久性错误（拒收）
- **WHEN** 请求向邮箱 E 发送验证码
- **THEN** 只尝试发送一次，返回 HTTP 400、错误码 `email_rejected` 并指出邮箱字段，不产生有效的验证码；该用户可以立即改用另一个邮箱请求发送

#### Scenario: AC-FR-SYS-020-10 无会话发送登录或重置用途的验证码
- **GIVEN** 已注册用户 U 的邮箱为 E；一个不带任何会话的访问者
- **WHEN** 请求向 E 发送"登录"用途的验证码，以及（60 秒后）发送"重置密码"用途的验证码
- **THEN** 两次都返回成功，E 收到两封分别说明用途的邮件；第一封邮件中的验证码已作废

#### Scenario: AC-FR-SYS-020-11 未注册的邮箱
- **GIVEN** 邮箱 N 不是任何已注册用户的邮箱
- **WHEN** 请求向 N 发送"登录"或"重置密码"用途的验证码
- **THEN** 返回 HTTP 404、错误码 `email_not_registered` 并指出邮箱字段，不发送邮件，不产生验证码

#### Scenario: AC-FR-SYS-020-12 验证码只能用于其用途
- **GIVEN** 已注册用户 U 持有一个发往其邮箱 E 的"登录"用途验证码
- **WHEN** 用该验证码重置密码，或用于更换邮箱
- **THEN** 验证码被判为无效（HTTP 400，指出验证码字段），密码与邮箱不变

## ADDED Requirements

### Requirement: FR-SYS-149 邮箱密码登录
已注册用户 SHALL 可以用邮箱与密码登录，不需要会话；邮箱去掉首尾空格并转为小写后比较。成功时后端 SHALL 按 FR-SYS-001 建立客户会话、按 FR-SYS-010 归集本设备游客会话的数据，并返回与 LINE 登录相同的身份信息。

| 情况 | 响应 |
|---|---|
| 邮箱未注册 | HTTP 404 `email_not_registered`，指出邮箱字段 |
| 尚未设置密码 | HTTP 400 `password_not_set`，指出密码字段 |
| 密码错误 | HTTP 401 `password_invalid`，指出密码字段，计入连续错误（FR-SYS-156） |
| 处于锁定期 | HTTP 423 `account_locked`，不检查密码 |

成功与失败都 SHALL 写入操作日志（FR-SYS-003），标明登录方式，SHALL NOT 包含密码。来源 IP 限流见 FR-SYS-157。

#### Scenario: AC-FR-SYS-149-01 登录成功
- **GIVEN** 已注册用户 U，邮箱为 `somchai@example.com`，已设置密码 P；一个不带会话的浏览器
- **WHEN** 用 ` Somchai@Example.com ` 与 P 登录
- **THEN** 返回成功与 U 的身份信息，并建立客户会话；之后用该会话调用需要登录的接口成功；操作日志有一条成功的邮箱密码登录记录

#### Scenario: AC-FR-SYS-149-02 未注册的邮箱
- **GIVEN** 邮箱 N 不是任何已注册用户的邮箱（含只存在于未注册用户 LINE 资料中的邮箱）
- **WHEN** 用 N 与任意密码登录
- **THEN** 返回 HTTP 404、错误码 `email_not_registered` 并指出邮箱字段，不建立会话

#### Scenario: AC-FR-SYS-149-03 密码错误
- **GIVEN** 已注册用户 U，已设置密码
- **WHEN** 用 U 的邮箱与错误的密码登录
- **THEN** 返回 HTTP 401、错误码 `password_invalid` 并指出密码字段，不建立会话；连续错误次数加 1；操作日志有一条失败的登录记录

#### Scenario: AC-FR-SYS-149-04 尚未设置密码
- **GIVEN** 已注册用户 U 在本变更前注册，没有密码
- **WHEN** 用 U 的邮箱与任意密码登录
- **THEN** 返回 HTTP 400、错误码 `password_not_set` 并指出密码字段，不建立会话，不计入连续错误次数

### Requirement: FR-SYS-156 密码连续错误锁定
- 同一用户连续 5 次密码错误后，SHALL 锁定该用户的密码登录 5 分钟（FR-SYS-149）。锁定期间即使密码正确也 SHALL 拒绝。
- 锁定开始时，连续错误次数清零。
- 成功的邮箱密码登录 SHALL 把连续错误次数清零；重置密码成功（FR-SYS-151）SHALL 清零并解除锁定。
- 锁定 SHALL NOT 影响 LINE 登录与邮箱验证码登录（FR-SYS-150）。
- 每次锁定 SHALL 写入一条操作日志（FR-SYS-003）。

#### Scenario: AC-FR-SYS-156-01 连续 5 次错误锁定 5 分钟
- **GIVEN** 已注册用户 U 已连续 4 次密码错误
- **WHEN** 第 5 次密码错误，随后在 5 分钟内用正确的密码登录
- **THEN** 第 5 次返回 HTTP 401，并写入一条锁定记录；正确密码的登录返回 HTTP 423、错误码 `account_locked`；5 分钟后用正确密码登录成功

#### Scenario: AC-FR-SYS-156-02 锁定期间仍可用验证码登录
- **GIVEN** 已注册用户 U 的密码登录处于锁定期，U 已取得一个"登录"用途的验证码
- **WHEN** 用 U 的邮箱与该验证码登录（FR-SYS-150）
- **THEN** 登录成功；U 的密码登录仍处于锁定期

#### Scenario: AC-FR-SYS-156-03 成功登录清零
- **GIVEN** 已注册用户 U 已连续 4 次密码错误
- **WHEN** 用正确密码登录成功，随后再连续 4 次输错
- **THEN** 账号没有被锁定，第 5 次用正确密码仍能登录

### Requirement: FR-SYS-157 免会话身份请求的来源 IP 限流
同一来源 IP 在任意连续 10 分钟内，对以下四类请求合计 SHALL 最多 30 次：
- 邮箱密码登录（FR-SYS-149）；
- 邮箱验证码登录（FR-SYS-150）；
- 重置密码（FR-SYS-151）；
- "登录"与"重置密码"用途的验证码发送（FR-SYS-020）。

超出的请求 SHALL 返回 HTTP 429、错误码 `auth_too_many`，且不检查密码或验证码、不发送邮件、不计入任何用户的连续错误次数。IPv6 地址按 /64 网段计数，与游客会话的限流相同（FR-SYS-010）。

#### Scenario: AC-FR-SYS-157-01 来源 IP 限流
- **GIVEN** 同一来源 IP 在最近 10 分钟内已发出 30 次上述请求
- **WHEN** 该 IP 再次用正确的邮箱与密码登录，以及另一个 IP 用同样的邮箱与密码登录
- **THEN** 前者返回 HTTP 429、错误码 `auth_too_many`，不建立会话；后者成功

### Requirement: FR-SYS-150 邮箱验证码登录
已注册用户 SHALL 可以用邮箱与"登录"用途的验证码（FR-SYS-020）登录，不需要会话。

- 验证码有效时，验证码 SHALL 被消费；后端 SHALL 按 FR-SYS-001 建立客户会话，按 FR-SYS-010 归集游客数据，返回与 LINE 登录相同的身份信息。
- 邮箱不是任何已注册用户的邮箱时，SHALL 返回 HTTP 404、错误码 `email_not_registered`。
- 验证码缺失、错误、过期、已使用、不是发给该邮箱的，或用途不是"登录"时，SHALL 返回 HTTP 400、错误码 `email_code_invalid` 并指出验证码字段，不建立会话；输错 SHALL 计入该码的错误次数（FR-SYS-020）。
- 邮箱验证码登录 SHALL NOT 改变密码的连续错误次数与锁定（FR-SYS-149）。
- 每次成功与失败的邮箱验证码登录都 SHALL 写入操作日志，标明登录方式，SHALL NOT 包含验证码。

#### Scenario: AC-FR-SYS-150-01 登录成功
- **GIVEN** 已注册用户 U（未设置密码也可以），已向其邮箱 E 发送"登录"用途的验证码并取得该码
- **WHEN** 用 E 与该验证码登录
- **THEN** 返回成功与 U 的身份信息并建立客户会话，验证码被消费；用同一验证码再次登录返回 HTTP 400

#### Scenario: AC-FR-SYS-150-02 错误的验证码
- **GIVEN** 已注册用户 U 持有一个有效的"登录"用途验证码
- **WHEN** 用 U 的邮箱与错误的验证码登录
- **THEN** 返回 HTTP 400、错误码 `email_code_invalid` 并指出验证码字段，不建立会话，该码的错误次数加 1

#### Scenario: AC-FR-SYS-150-03 用途不符
- **GIVEN** 已注册用户 U 只持有一个"重置密码"用途的验证码
- **WHEN** 用 U 的邮箱与该验证码登录
- **THEN** 返回 HTTP 400、错误码 `email_code_invalid`，不建立会话

#### Scenario: AC-FR-SYS-150-04 未注册的邮箱
- **GIVEN** 邮箱 N 不是任何已注册用户的邮箱
- **WHEN** 用 N 与任意验证码登录
- **THEN** 返回 HTTP 404、错误码 `email_not_registered`，不建立会话

### Requirement: FR-SYS-151 通过邮箱验证码重置密码
已注册用户 SHALL 可以用邮箱、"重置密码"用途的验证码（FR-SYS-020）与新密码重置密码，不需要会话；尚未设置密码的已注册用户用同一方式设置密码。

后端 SHALL 依次校验：邮箱已注册（否则 HTTP 404 `email_not_registered`）；新密码符合 FR-SYS-152（否则 HTTP 400 指出密码字段，验证码不被消费）；验证码有效且用途为"重置密码"（否则 HTTP 400 `email_code_invalid` 指出验证码字段，密码不变）。

成功时 SHALL 在同一事务中消费验证码、保存新密码的哈希、清零连续错误并解除锁定（FR-SYS-156）、使该用户的全部客户会话失效、在本设备建立新的客户会话并归集游客数据（FR-SYS-010）、写入不含密码与验证码的操作日志，并返回与 LINE 登录相同的身份信息。

#### Scenario: AC-FR-SYS-151-01 重置成功并登录
- **GIVEN** 已注册用户 U：在设备 A 与设备 B 上各有客户会话，密码登录处于锁定期，已取得一个"重置密码"用途的验证码
- **WHEN** 在不带会话的设备 C 上用 U 的邮箱、该验证码与符合规则的新密码 P2 重置密码
- **THEN** 返回成功与 U 的身份信息，设备 C 得到新的客户会话
- **AND** 设备 A 与 B 的会话调用需要登录的接口返回 HTTP 401
- **AND** 锁定已解除，可以立即用 P2 登录，旧密码登录返回 HTTP 401
- **AND** 操作日志有一条重置密码记录

#### Scenario: AC-FR-SYS-151-02 新密码不符合规则
- **GIVEN** 已注册用户 U 持有一个有效的"重置密码"用途验证码
- **WHEN** 用 7 个字符的新密码，或只含字母的新密码重置
- **THEN** 返回 HTTP 400 并指出密码字段，密码不变，验证码仍然有效

#### Scenario: AC-FR-SYS-151-03 验证码无效
- **GIVEN** 已注册用户 U，只持有一个"登录"用途的验证码
- **WHEN** 用该验证码与符合规则的新密码重置
- **THEN** 返回 HTTP 400、错误码 `email_code_invalid` 并指出验证码字段，密码不变，U 的会话都不受影响

#### Scenario: AC-FR-SYS-151-04 未设置密码的用户设置密码
- **GIVEN** 已注册用户 U 没有密码，已取得"重置密码"用途的验证码
- **WHEN** 用该验证码与新密码 P 重置
- **THEN** 成功；之后可以用 U 的邮箱与 P 登录

#### Scenario: AC-FR-SYS-151-05 未注册的邮箱
- **GIVEN** 邮箱 N 不是任何已注册用户的邮箱
- **WHEN** 用 N 重置密码
- **THEN** 返回 HTTP 404、错误码 `email_not_registered`，不改变任何数据

### Requirement: FR-SYS-152 客户密码规则与存储
客户密码 SHALL 满足以下规则：
- 长度为 8 到 64 个字符，首尾空格计入长度、不被去除；
- 至少包含一个英文字母（A–Z 或 a–z）；
- 至少包含一个数字（0–9）。

规则 SHALL 在注册（FR-SYS-014）与重置密码（FR-SYS-151）时由后端校验；页面 SHALL 在提交前用同一规则提示。

存储：
- 密码 SHALL 以带盐的强单向哈希（与平台管理员口令相同的算法）存储。
- 密码 SHALL NOT 以明文出现在数据库、接口响应、服务端日志或操作日志中。
- 客户密码与平台管理员口令 SHALL 互相独立。

#### Scenario: AC-FR-SYS-152-01 符合规则
- **GIVEN** 一个注册或重置密码的请求
- **WHEN** 密码分别为 `abcd1234`（8 个字符）与一个含字母和数字的 64 个字符的密码
- **THEN** 都通过规则校验

#### Scenario: AC-FR-SYS-152-02 不符合规则
- **GIVEN** 一个注册或重置密码的请求
- **WHEN** 密码分别为 `abc1234`（7 个字符）、65 个字符、`abcdefgh`（无数字）、`12345678`（无字母）
- **THEN** 每一个都返回 HTTP 400 并指出密码字段

#### Scenario: AC-FR-SYS-152-03 不出现明文
- **GIVEN** 一次注册、一次密码错误的登录与一次重置密码
- **WHEN** 检查数据库、接口响应、服务端日志与操作日志
- **THEN** 都不出现所用密码的明文
